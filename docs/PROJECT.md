一句话：三轮翻牌短决策。系统根据用户怎样找证据、怎样用证据，形成有行为依据的画像，当场给出一关个性化研究任务，任务做完再更新画像。

本文只写**已经实现**的内容；PRD 里有、但这次没做的，在第 9 节“实现状态”里明确写“未实现”。

## 1. 目标用户与使用场景

- **适合谁**：刚接触 PandaAI、想学怎么用数据检验一个说法的新用户。
- **什么时候用**：在群里、帖子里听到“这只票跑赢市场”“它很稳”“放量了要涨”这类说法，不知道该先查什么。
- **首次体验时长**：以真实试玩为准（YOU-173 记录中），这里不写未经测量的时间。

## 2. 玩法

### 第一幕：三轮

每轮是一句关于真实 A 股标的的说法（标的匿名为 A / B / C，揭晓后才显示代码）：

| 轮次 | 说法类型 | 关键牌 | 证据结论 |
|---|---|---|---|
| R1 | 过去 60 个交易日跑赢指定基准 | 🦊 同期对照 | 不支持 |
| R2 | 过去三年总体上涨、最大回撤不到 15% | 🐘 更长历史 | 支持 |
| R3 | 20 个交易日后收盘价会更高 | 🐆 近期量价 | 证据不足（对未来的断言） |

每轮的步骤：

1. **第一反应**：支持 / 不支持 / 说不准（提示：这是对这句话的第一判断，不是交易选择）。
2. **翻牌**：三张牌最多翻两张，也可以不翻；“这张图怎么看”不占翻牌次数。
3. **最终判断**：支持 / 不支持 / 证据不足。
4. **你的下一步**：跟 / 不跟 / 先看看。界面上只是一行小字，揭晓前不显示代币。
5. **追问**（最多一次，可跳过）：最终判断为证据不足 → “还缺什么”；翻过关键牌但结论与证据不符 → “主要依据什么”；选“先看看” → “在等什么”。
6. **锁定 → 揭晓**：判断线在上（依据与结论一致 / 未查看关键证据 / ……，不用“正确 / 错误”），代币线在下且更小；补全没翻的牌（标明补全不改写本轮判断）；获得一张方法卡。

### 结果与下一关

- **人物卡**：本局交易物种、本局观察（O1–O4）、帮助偏好、还不知道的事、换成交易语言来看、下一关与推荐理由。
- **依据页**：每条观察可展开，看到发生在哪一轮、做了什么、命中的规则编号、帮助暴露和其他可能解释。
- **分享卡**：只有物种和“本局”限定，不含任何行为记录。
- **任务 A「同一起点，再比一次」**：新标的 D。步骤 1 必须先把两条线拖到同一起点才能提交；步骤 2 把窗口拉长到约 3 年，核对累计涨跌和最大回撤。
- **任务 B「换一段数据，还成立吗？」**：猎豹题。先锁定规则，再看展示段，再打开没给看过的检验段，最后回答“这两段数据分别支持什么观察”并选出依据的数字。
- **画像更新页**：任务中的新情境单独记录，不改写第一幕的观察。

## 3. 画像维度与行为依据

所有观察都来自事件序列，由 `src/engine/evaluate.ts` 计算，同一输入必得同一输出。**收益不进入能力**：`evaluate` 的输入里没有收益字段，代币结算在 `settle.ts` 里单独计算，`evaluate` / `recommend` 都不导入它（有测试检查导入关系）。

| 观察 | 看什么行为 | 形成什么判断 | 哪里还不确定 |
|---|---|---|---|
| O1 用参照检验 | R1 翻没翻 🦊 同期对照，最终判断是否和对照证据一致 | 翻了且一致 → 观察到（O1-a）；翻了但结论相反 → 有冲突（O1-b）；没翻 → 未观察到（O1-g），猜中方向也不算 | 只有一个情境时标“只见一次”；追问选“图没看懂”记为理解待确认（O1-c） |
| O2 用长窗口检验 | R2 翻没翻 🐘 更长历史，判断是否和累计涨跌、最大回撤一致 | 同 O1 的规则（O2-a / b / g …） | 同上 |
| O3 识别证据边界 | R3 对未来的说法：看没看量价、是否选证据不足 | 看过量价仍选证据不足，且在可判定的轮次里下过明确判断 → 一致（O3-a）；看过量价就对未来下判断 → O3-d（推荐猎豹题定向练习） | 没看就选证据不足（O3-b）只算尚待确认 |
| O4 根据新证据修正判断 | 第一反应和关键证据冲突时，最终判断有没有跟着证据走；任务里的“先猜后验”同理 | 调整了 → O4-a；没调整 → O4-c | 第一反应也可能是随手点的 |
| O5 在给定规则下比较两段样本 | 任务 B 提交的结论和依据是否与两段数据一致 | 一致 → O5-t（看过提示或重试则记为在帮助下） | 只说明能按给定规则读样本，不代表会自己设计回测 |

另外三项：

- **本局交易物种**（偏好，不是能力）：只统计“说法没有直接点名的那张牌”的首翻。某种牌至少 2 次且最多 → 狐狸 / 大象 / 猎豹；平局 → 混合倾向；能计入的首翻太少 → 物种尚未显形。
- **帮助偏好**：用户主动选过的档位优先，其次是“图没看懂”这类理解信号，再次按展开解释的次数推断。
- **行动习惯**（`src/engine/habits.ts`）：判断和下一步同向 / 不同向的轮次、证据不足时选了什么、跟过哪些押注形态、每轮的决策链。只计数，不评高低，不进入能力观察；同一形态至少跟 2 次才算常押，常押只影响任务 B 的默认主题。

帮助暴露：看过方向性解释、提示、示范或答案反馈之后完成的，一律记为“在帮助下”，之后切到“我自己来”也不会清除。

## 4. 推荐逻辑

由 `src/engine/recommend.ts` 计算，同样不读代币和收益。

- **路由**：S1 = O1 有两次独立一致，或任务 A 步骤 1 已完成；S2 同理对应 O2 和步骤 2。两者都满足 → 任务 B（R-B / R-B-progress）；否则做任务 A 缺的那一步（R-A1）或两步（R-A2）。完成基础步骤就进 B，不会因为 K 没涨而把人送回 A。
- **先猜后验**：O4 不是“观察到”时开启，前后两次答案都记录，不强迫改。
- **协助档位**：按帮助偏好给默认值，用户可随时切换。
- **任务 B 主题**：用户明确选题 > O3-d 定向练习 > 常押形态 > 物种默认 > 选题入口。常押形态和物种指向不同主题时，默认高亮常押形态的主题，并同时写出两个来源，由用户决定。三个主题（猎豹 / 大象 / 狐狸）都已发布，任务开始前可以换题，开始后不换。

### 两条模拟路径的差别（由引擎生成，见 `docs/examples/`）

| | 路径乙（关键牌都看了，第 3 轮对未来下了判断） | 路径甲（翻了牌，但没翻关键牌，结论碰巧对） |
|---|---|---|
| 物种 | 大象 | 狐狸 |
| O1 / O2 | 观察到（只见一次） | 未观察到（猜中方向不算查证） |
| O4 | 观察到 | 尚不确定 |
| 推荐 | 任务 A 两步，“只见过一次，换一只股票再练一次” | 任务 A 两步，“这几轮还没看到你……，这关专门练这一步” |
| 先猜后验 | 关 | 开 |

两条路都去任务 A，但理由和是否先猜后验不同。评委面板里可以把乙的 R1 最终判断改成“支持”，现场看到 O1 从“观察到（O1-a）”变为“尚不确定（O1-b）”，推荐理由随之改成“结论和看到的证据还没对上，再比一次”。

## 5. Panda Data 使用方式

前端只加载离线生成的静态 JSON，评审时不需要 Panda Data 账号。生成脚本在 `scripts/`，账号只从本地 `.env` 读取。

| 数据文件 | 脚本 | 实际调用的接口 |
|---|---|---|
| `cases_visible.json`、`cases_reveal_R1–R3.json` | `build_cases.py` | `get_stock_daily_pre`、`get_index_daily`、`get_index_weights`、`get_adj_factor`、`get_industry_constituents`、`get_trade_cal` |
| `taskA.json` | `build_taskA.py` | `get_stock_daily_pre`、`get_index_daily`、`get_index_weights`、`get_industry_constituents` |
| `taskB_cheetah.json` | `build_taskB.py --topic cheetah` | `get_stock_daily_pre`、`get_index_weights`、`get_adj_factor`、`get_trade_cal` |
| `taskB_elephant.json` | `build_taskB.py --topic elephant` | `get_stock_daily_pre`、`get_index_weights`、`get_trade_cal` |
| `taskB_fox.json` | `build_taskB.py --topic fox` | `get_stock_daily_pre`、`get_index_daily`、`get_index_weights`、`get_trade_cal` |

口径：前复权日线；累计收益 = 末值 ÷ 首值 − 1；最大回撤 = 从此前最高点往下跌的最大比例；量比的均量不含触发当日；决策时只看到 T 日收盘及以前；“跟”的演示按 T+1 开盘进、T+20 收盘出，不计费用和滑点。Python 与 TS 的计算公式共用一组固定用例，保证两边结果一致。

**揭晓前不持有未来数据**：揭晓前只加载 `cases_visible.json`（只有相对日期，没有代码和名称）；某一轮锁定后才请求这一轮的揭晓文件。这是防止界面误用未来数据的工程边界，不是防作弊——静态站点的文件用户都能在网络面板里看到。

任务 B 三个主题共用股票池（2021-01-04 的中证800 成分）、分段（展示段 2021–2022，检验段 2023–2024）、不重叠规则和判定函数，信号与主指标各自冻结。样本处理分别见 `docs/taskB-cheetah.md`、`docs/taskB-elephant.md`、`docs/taskB-fox.md`：

- **猎豹题**（放量上涨后 20 个交易日）：两段都没有观察到达到阈值的优势。信号组收益为正的比例比基准组低 0.1 和 1.1 个百分点，平均收益却更高，界面会说明比例和均值回答的是不同问题。
- **大象题**（过去 250 日累计上涨且最大回撤 < 15%，之后 250 日）：两段都达到阈值（+6.4 和 +32.8 个百分点）。但持有约一年，两年分段里每只股票每组最多一条记录，基准组几乎都在分段第一个月末进场，信号组进场月份分散，两组经历的行情不同；界面在两段并排处直接写出这一点，不把达到阈值说成规则有效。
- **狐狸题**（上月跑赢沪深300，次月超额收益）：两段都没有观察到达到阈值的优势（−0.9 和 −1.0 个百分点）。比较的是超额收益，不是普通上涨。

所有数据文件都通过 `contracts/` 的 schema 校验（`src/data/contracts.test.ts`）。公开展示许可尚未获得 PandaAI 明确答复，暂按最保守方式处理：只发布归一化曲线和派生统计，不发布原始行情。

## 7. 已知局限

- 第一幕只有三轮，每项能力最多只见一次，所以人物卡始终标“只见一次”；信息风格不等于稳定偏好。
- 案例是按规则筛选出的教学案例，不代表随机样本。
- 任务 B：股票池按快照日冻结，存在选择偏差且只覆盖中证800 大中盘；不重叠只保证同一只股票的持有期不重叠，不同股票同期样本高度相关，不等于独立；阈值只是练习的描述标准，不是显著性门槛。
- 收益是简化模拟，没有计入交易成本；T+1 开盘涨停时实际可能买不到。
- 不测现实风险承受能力；追问是自述，不作为能力证据。
- 单元测试只证明实现符合规则，不证明心理测评效度。
- 模拟路径（甲 / 乙 / 乙′ / 乙″ / 丙）都标“模拟”，与真实试玩记录分开。

## 8. 评委面板

`?judge=1`。选择预设路径或当前体验记录，逐轮改首翻、次翻、最终判断、行动、追问，建立分叉后与基线并列比较，可逐步撤销；画像没变时会解释原因（例如“交易行动不参与能力推断”）。“反例检查”一键运行 PRD §9 的 9 项检查，显示预期、实际和是否通过；同样的 9 项在 Vitest 里也有自动测试，并用故意改坏的引擎证明检查会变红。
