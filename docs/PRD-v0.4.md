## 0. 先冻结的方向

**第一，主角是玩家，不是测评系统。** 玩家进入时想完成一段冒险，不是协助系统填满画像维度。把人物报告隐藏后，战斗、奖励、成长与下一场仍必须成立。

**第二，借鉴构筑冒险和资源调度机制，不复制现成作品。** 参考《杀戮尖塔》《月圆之夜》的战斗—奖励—构筑—分叉结构，参考《炉石传说》的过载、跳费和组合关系。卡牌名称、世界观、美术、文本与具体平衡重新设计；不复刻角色、卡面或品牌元素。

**第三，确定的代价、不确定的风险、人的感受，是三件事。** “下回合少两点能量”是已知的跨回合成本；“契约下一段价值未知”才包含结果不确定性；“实际发生后比预想更难受”属于自我预期校准。不能用同一条“风险偏好分”混合解释。

**第四，游戏打法与现实交易类型没有自动翻译关系。** 攻击牌多不等于激进投资者，护甲多不等于稳健投资者，过载不等于偏爱杠杆，跳费不等于长期价值投资。画像必须经过“行为事实—可选机会与约束—有限解释—推荐用途”四步。

**第五，输赢可以有意义，但不成为人的等级。** 金币与损失会改变购买能力和后续局面；战斗可以失败。这不等于能用通关、赚到多少或忍受多少损失，评定金融能力、人格优劣或现实财务承受力。

**第六，观察必须让位于合理玩法。** 允许强力连招、正确斩杀、利用规则获益、在新信息出现后改变计划。不能为了“看见代价”强行追债，也不能为了“测出反差”导演一次损失。

### 0.1 这次重构解决什么

v0.3 中的方法卡主要服务后续练习，固定投入和答题行为没有形成足够强的局内成长闭环。[P1：§2、§8] 本版把“赢下一场、拿到新牌、形成组合、经营下一段路”作为玩家的主要动机，把数据和观察放进有实际后果的选择里。

**首要成功条件：**首次试玩者打完第一场、选完奖励牌后，愿意继续第二场，而且能说出“我想试试刚拿到的这张牌”。

**赛题闭环：**参与冒险 → 留下带情境的行为 → 形成有证据的本局观察 → 推荐相关工具或研究任务 → 实际操作。不是“玩一局后附赠一段性格文案”。

## 1. 产品定位、用户与体验边界

### 1.1 产品定位

一款手机优先的单人短篇卡牌构筑冒险，首章名为“晨光小城 · 守灯之旅”（此前工作名“雾城归途”）。玩家使用同一个基础角色，从混合基础牌组开始，通过战斗奖励、商店与升级构筑自己的解法；同时安排一段旅程中的可用资源。

角色不预设为狐狸、猎豹、大象，也不先要求玩家选择激进／保守职业。角色外观只影响表达，不改变判定和数值。首版没有多人竞技、抽卡付费、现金奖励或真实交易。

### 1.2 目标用户

对轻量卡牌游戏或投资探索感兴趣、不一定懂金融术语的普通用户。入门不要求玩过炉石或尖塔；教程通过一场真正的短战斗完成，不先讲一页金融概念。

首个完整版本以 **一章约 8—12 分钟**为体验设计目标，必须用试玩检验。第一场及选牌应尽快给出价值。演示视频可以为 3—5 分钟，不把视频长度误写成全部游玩时长。

### 1.3 产品承诺

我们提供“本局怎样安排资源、使用信息、应对变化”的观察，帮助选择下一步探索内容。**不承诺通过一局游戏发现稳定交易人格，不生成现实投资风险等级，不推荐具体证券、产品或现实仓位。**现实资金用途、负债、收入和必要支出没有被收集时，统一标明“现实财务承受能力未评估”。

研究发现，不同风险偏好测量任务所得结果可能不一致；本项目据此采用保守的迁移边界，而不是声称“游戏一定比问卷更真实”。研究也不能替代对本产品的验证。[R1]

## 2. 核心体验：这趟冒险是我的

### 2.1 世界与目标

玩家进入一座晨雾渐散的阳光小城，目标是完成守灯者的挑战、取回灯火，并走出城门。城中有旅行者、补给站和临时市集。按用户最新方向，采用面向大众的明亮手绘童话：暖色石墙、绿植、开阔天空、浅雾和柔和阳光；人物友善、有探索感。避免阴森夜景、恐怖怪物、压迫性黑色遮罩，不做金融终端，也不靠恐吓和刺激制造损失感。

**主目标是完成冒险，不是最大化金币。** 金币是维持选择空间的工具：可以补给、升级、买牌、查资料，也可以暂时投入一份随旅程变化的契约。没有“金币最多的人才算高手”的结算。

### 2.2 三层循环

**回合循环：**读敌人意图 → 安排能量和手牌 → 出牌形成效果 → 承受或避免敌人行动 → 下一回合。

**构筑循环：**赢得战斗 → 三选一或不拿 → 新牌进入牌组 → 下一场形成新的配合 → 在升级和购买中继续调整。

**旅程循环：**查看路线与资源 → 选择补给、情报及契约参与量 → 经历战斗和资源变化 → 到营地重新安排 → 前往最终目标。

观察和推荐读取这些过程，不在每次出牌之后插入测评问题。

### 2.3 首章节点

| 节点 | 发生什么 | 玩家真正需要决定什么 |
|---|---|---|
| N0 城门 | 一句话目标、告知、基础牌组 | 开始；可关闭非必要动画 |
| N1 门卫战 | 简短教学战斗，胜利后第一次三选一 | 如何打牌；想尝试哪张新牌 |
| N2 第一营地 | 商店、已知路线概要、首次契约入口；可选预期卡 | 当前消费与留存；是否参与契约；先看什么信息 |
| N3 第一处分叉战 | 开战前有可跳过的现金补给；两种已标明特点的敌人，结算奖励 | 是否先消费；哪个挑战更适合当前牌组和状态 |
| N4 中途营地 | 第一段契约揭晓、实际收回操作、补给或升级 | 当前还要保留多少参与量；下一步缺什么 |
| N5 第二处分叉战 | 再次经过路边现金补给；两种挑战，胜利后再选牌 | 是否使用保留现金；如何补完整构筑 |
| N6 最后营地 | 第二段揭晓、最后购买机会；可提前返程 | 用现有资源准备决战，或带着当前发现离开 |
| N7 守灯者 | 最终战，检验已形成的组合 | 在敌人不同阶段安排爆发与成长 |
| N8 归途 | 结束账本、冒险战报、可展开的本局观察 | 再来一局、查看依据、进入推荐任务 |

P0 地图骨架固定，分叉提供不同敌人／奖励配置，不生成大型随机地图。每个分叉至少有两个实际可走、差异清楚的选项；否则只能记录“经过”，不能记录为偏好选择。

### 2.4 结束、失败与暂停

取回灯火并完成最终战记为 `cleared`；在营地选择提前返程记为 `returned`；生命归零记为 `defeated`。三者都可看战报和研究任务，但不能把提前返程写成“胆小”，也不能把失败写成金融能力不足。

关页面、网络中断、暂停记为 `suspended`，保留本地进度，不自动解释为返程、卖出或承受不了。重开新局可免费进行，不保留强度优势；已知案例重玩需要标注，不能算独立证据。

## 3. 资源系统：每种资源只讲清楚自己的作用

| 资源 | P0 作用与初值 | 生命周期 |
|---|---|---|
| 生命 | 示例上限 42；归零结束当前冒险 | 跨战斗保留，可在营地补给 |
| 护盾 | 吸收本次敌人阶段伤害 | 下次玩家回合开始时清空，不跨战斗 |
| 能量及容量 | 每场起始容量 3；每回合恢复；容量上限 6 | 成长与过载仅在本场战斗有效 |
| 金币 | 初始示例 60；支付卡牌、补给、升级、情报 | 跨节点保留；不兑换现金 |
| 契约份额 | 使用金币购买的独立份额；按历史派生价格记值 | 不等于现金；只在允许的营地提交回收 |

契约份额不是第二种可自由支付的货币。界面同时显示“可用金币”和“契约参考价值”，绝不把尚未回收的份额计入商店可用余额。

不增加“勇气值”“理性值”“风险天赋”等人格化资源。状态条中不显示评分或推荐等级。

## 4. 战斗与构筑规格

### 4.1 基础回合

每场使用当前完整牌组，开局按固定种子洗牌。玩家每回合抽 5 张，手牌上限 8；抽牌超过上限的牌公开进入弃牌堆。抽牌堆不足时，使用该场的独立随机流重洗弃牌堆。保留牌占用手牌容量。

敌人当前回合的行动在玩家出牌前可见。首版以单个敌人为主，不做随从站位、召唤物、复杂目标选择或隐藏反制。先把出牌顺序和跨回合安排做好。

玩家回合开始顺序固定：清除上回合护盾 → 结算本回合过载 → 按容量恢复可用能量 → 抽牌 → 展示敌人本回合意图。玩家出牌后可主动结束回合；敌人执行意图；未保留手牌进入弃牌堆，临时能量清空。每一步均写入确定性战斗日志。

牌打出前先完成费用、目标和过载上限等全部合法性检查；通过后先支付费用，再登记过载等必付代价，再按文本顺序执行效果。击杀即终止敌人行动，进入战斗胜利；不在目标死亡后继续要求玩家承受本来已避免的攻击。

“消耗”表示本场进入消耗区、不再抽到，不是永久删除牌。战斗结束后，消耗牌回到该局牌组；护盾、额外容量、过载和回合增益清空，生命和金币保留。

### 4.2 过载：提前使用行动，不是金融杠杆测验

本版机制：带“过载 X”的牌在打出时登记 X 点锁定，**下一玩家回合少恢复 X 点能量，仅持续那一个回合**。界面始终显示“现在可用／本场容量／下回合锁定”。

P0 简化：本回合累计待结算过载不能超过当前容量；超过时不能打出，并说明原因。此规则是本游戏的简化，不宣称等同炉石的全部边界规则。

设容量为 C，本回合待结算值为 Q：下回合可用能量为 `max(0, C - Q)`，进入下回合后待结算值归零；本回合新增的过载另计。暂时获得的能量可以让当前可用能量超过容量，但不会增加容量，也不能当作解除已锁定能量。

**战斗胜利后清除未结算过载。** 用过载完成斩杀是合法战术，不为“体现借贷代价”追加下一场惩罚。过载是否过强由卡牌效率、手牌消耗、非斩杀回合与敌人节奏共同检验，不由道德化规则修正。以后若设计跨战斗负担，必须另起机制、事先明示，不悄悄改过载含义。

同一机制可用于进攻，也可用于紧急防护；这本身就能避免“用了过载＝好冒险”的错误对应。玩家为了不死使用过载，可能恰恰是在降低当前危险。

### 4.3 成长／跳费：牺牲当前，增加本场后续容量

“成长 1”将本场能量容量增加 1，新增格为空，**不立刻恢复本回合能量**，从下一回合起参与恢复，上限 6。没有每回合自然增长；普通情况下每回合都是 3，额外容量由牌带来。

在容量已满时，只含成长的牌不能打出；有其他效果的成长牌可正常执行其他效果，但明确提示本次不能再增加容量。打出前预览容量及下一回合可用能量，不能用术语隐藏其空过代价。

这是参考跳费思路后为短篇冒险制定的规则；不是照搬炉石当前卡牌费用或职业平衡。官方《野性成长》以增加空法力水晶表达容量增长，官方平衡说明也曾强调增加成长当回合的代价；本版据此关注“当前成本必须可感知”，不引用其数值作为平衡结论。[R2]

容量在新战斗重置。选择成长不自动等于耐心或长期投资偏好：它可能是某场战斗的最优解，也可能是在早期承受更大生存风险。

### 4.4 初始牌组与原型牌池

初始牌组 **10 张、6 种**：敲击 ×3、格挡 ×3、整理 ×1、借火 ×1、引根 ×1、缓步 ×1。玩家从一开始就能接触预支与成长，但教程不要求必须使用某一张。

P0 共 **14 种牌**，下面全部是新设计的原型数值。卡牌只显示作用，不标“激进牌／稳健牌”。

| ID／牌名 | 费用 | 基础效果 | 单次升级效果 |
|---|---:|---|---|
| C01 敲击 | 1 | 造成 6 点伤害 | 伤害 9 |
| C02 格挡 | 1 | 获得 6 点护盾 | 护盾 9 |
| C03 整理 | 1 | 抽 2 张牌 | 抽 3 张 |
| C04 借火 | 0 | 本回合获得 2 点能量；过载 2；消耗 | 获得 3 点能量，其余不变 |
| C05 引根 | 2 | 成长 1；消耗 | 费用降为 1 |
| C06 缓步 | 1 | 获得 4 护盾，抽 1 张牌 | 护盾 6 |
| C07 连刃 | 1 | 连续造成 3 次 3 点伤害 | 每次 4 点 |
| C08 余烬 | 1 | 本回合后续攻击牌的每一段伤害 +2 | 每段 +3 |
| C09 引雷 | 1 | 造成 12 点伤害；过载 1 | 伤害 16 |
| C10 临时壁垒 | 1 | 获得 14 护盾；过载 1 | 护盾 18 |

“余烬”只增强攻击牌对敌人直接造成的伤害，不增强自伤、反伤或重复触发自身。P0 无复制牌与无限抽牌引擎。C14 无其他手牌时不能指定保留，但仍可抽牌；消耗效果照常发生。

C12、C13 的保留持续到打出；C14 赋予的保留只跨一次回合结束。卡牌细节页明确差别。牌组不满或未抽到某牌不能被解释为主动放弃该玩法。

### 4.5 两条构筑方向，也允许混合

**借力连击。** 用借火增加当回合动作，用整理找到组件，先打余烬再打连刃，或用引雷收尾。以未升级卡为例，余烬＋连刃造成 `3 × (3+2) = 15` 点伤害，不是原来的 9 点。其代价是手牌和后续能量受限，不是简单“血越少伤害越高”。

**成长兑现。** 第一回合用引根＋格挡，下一回合容量达到 4；合适时再用培育到 5，使参天一击／树冠守望与一张低费牌能在同一回合打出。它需要通过早期回合，也要有足够手牌使用新增能量；容量增长本身不自动赢。

**混合不是异常。** 借火可以帮助提前打出成长；成长可以改善后续过载回合的可用能量；临时壁垒可以保护成长，也可以给连击牌组争取抽牌机会。不得为了方便分类禁止混搭。

### 4.6 选牌、升级与奖励

每次非最终战胜利获得金币和“三选一／都不拿”。拿牌后立即进入牌组，下一场可抽到。不拿牌不扣分，牌越多不一定越好。升级有可见的前后效果，不用隐藏数值。

演示种子的奖励和商店目录在开局前固定，并保证两条方向都可获得关键组件；不根据画像悄悄喂牌。可用初始目录：第一次奖励提供连刃／培育／临时壁垒；后续目录同时包含连击增强、成长兑现和通用牌。精确种子文件需与卡牌配置一起冻结。

P0 不做永久强度解锁。已获得卡牌可加入离局图鉴，图鉴是收藏记录，不改变下一局基础能力。可以展示最高单回合组合、最关键的一张牌等**游戏成就**，但它们不进入交易观察。

### 4.7 敌人要给不同打法真实空间

P0 只需 3 类普通敌人（教学使用其中的弱化版）和 1 个 Boss。配置目标如下，不在此声称已完成平衡：

| 敌人原型 | 明示节奏 | 要制造的决策 |
|---|---|---|
| 追灯者 | 前两回合进攻较强，随后有喘息 | 当前爆发／临时壁垒是否值得透支下一回合 |
| 苔壳卫兵 | 初期压力低，随后输出增长 | 能否抓住成长窗口，而非无限准备 |
| 摆钟侍从 | 大攻击与整备交替 | 过载落在哪一回合、何时保留关键牌 |
| 守灯者 | 固定的整备—压迫—恢复周期，阶段提示清楚 | 同一副牌怎样在不同节奏下切换 |

敌人强度不由玩家的金融观察、预测答案、金币损失或“承受力”动态调整。通过公开的敌人增长机制避免无代价拖延，不能偷偷加伤害惩罚“太保守”。没有刷钱、刷治疗的无限循环。

**可直接起原型的敌人初值：**教学门卫 18 生命，循环“攻击 4／获得护盾 4／攻击 6”；追灯者 34 生命，循环“攻击 8／攻击 8／攻击 3”；苔壳卫兵 42 生命，循环“获得护盾 6／攻击 5／攻击 9”；摆钟侍从 38 生命，循环“攻击 12／获得护盾 6／攻击 4”；守灯者 90 生命，循环“攻击 6／攻击 14／获得护盾 10”。这些是待调试起点，不是平衡结论。

教学战不增长。其他战斗从第 10 个敌人阶段起，每个敌人阶段使其永久攻击加成再增加 2，开始前就展示该规则及当前加成；护盾值不随之增加。敌人护盾在每次敌人阶段开始时清空，再执行该阶段行动，因此其获得的护盾会持续到下一次玩家行动。P0 可暂统一普通战奖励为 12；只有配置明确标为高报酬挑战时才用 18，不能因对玩家判断“更危险”而临时改奖励。

## 5. 旅程经营：数据需要改变能做什么

### 5.1 营地中的真实取舍

营地是同一个操作界面，不是突然跳出的金融测评。玩家可以查看牌组、购买、保留金币、查额外资料或管理契约。操作顺序自由，提交需要支付的行为后不能免费撤销；提交前有明确金额预览。

首轮价格示例：10 金币补充 10 生命；20 金币升级一张牌；25 金币买一张牌；4 金币查一份额外资料。教学战奖励 12 金币，普通战 12、强敌战 18。所有商品在购买前展示效果及价格；不采用个性化定价。

N4 和 N6 各有一次免费的“休息恢复 6 生命／整理升级一张基础牌”二选一，确保不参与契约或手头现金不足仍有继续玩下去的操作空间。一次不能两者都选；免费选项同样不是能力考试。

选择 0 参与、保留全部现金，应当有可行的通关路线；选择参与契约也不应变成唯一能买到核心组件的方式。

**N3、N5 开战前各有一处可跳过的路边补给，只卖 10 金币的生命补给和 20 金币的升级，不办理契约回收。**它不增加独立地图节点、不推进行情。上一营地事先说明这里的商品与现金要求。这样，保留现金能在下一营地之前发挥作用；否则，如果所有消费都恰好发生在可回收之后，“暂时不能用钱”只是文案，不是真正的流动性取舍。

### 5.2 随行契约

P0 只做 **一种合约机制、一条在本局固定的历史派生路径**，不用一开始就设计多资产组合。不同局可抽取不同的、已说明选案方式的案例。

玩家在 N2 决定参与金额 A，可选择 0，也可在可用金币以内自行调整。提供 0／25%／50%／75% 的快捷选择及金额调整，完整参与仍可通过调整选择。比例仅是操作便利，不是推荐档位。没有“推荐仓位”的高亮。

基本风险、回收节点、价格口径和不能保证本金等规则免费可见。确认前显示“提交后暂不可用 A 金币；剩余可用 C−A”。不要求玩家投入，也不因零参与判定保守、不会研究或不能进入后续内容。

份额价值随真实历史派生价格变化，涨跌都可能发生。N4、N6 可以选择继续、回收一半当前份额、全部回收；P0 不追加投入、不借钱、不卖空、不做杠杆。P1 才考虑增加第二份契约，届时再设计集中／分散维度；**P0 不输出分散投资能力。**

### 5.3 为什么不只是一个股票小游戏

契约影响的是同一局冒险中的购买能力：回收后可能补得起一次升级，保留份额则可能放弃眼前购买。卡牌战斗不是答题奖励，契约也不单独构成收益排行榜。

战斗技能、手牌和生命状态会改变金钱的用途。因此，一笔相同金额的投入在两局里可能有不同含义；不能用固定比例阈值直接贴人格。画像必须看到购买目录、生命、牌组、现金和路线，而不只是参与比例。

### 5.4 时间与结算顺序

在 N2 决策时，契约数据只显示到 `T0` 收盘，确认的金额预留为待执行资金；在之后的第一个交易日开盘 `O[T0+1]` 成交，得到份额。营地的未来报价不能预先显示。

N3、N5、N7 分别推进一段冻结的历史时间，默认每段 20 个交易日，可根据数据冻结为其他长度；所有路线消耗相同段数，战斗打了几回合不改变行情推进。路线不同带来的“时间长短”不在 P0 伪装为持有期偏好。

到 N4／N6 时，先显示截至 `T1`／`T2` 收盘的当前参考价值，再记录当下选择；回收指令在下一交易日开盘执行。界面写明“将按下一报价结算，实际到账可能不同”。**到账前不能把预计回收数当现金消费。**提交后推进到执行报价、完成到账，再开放该营地购买；选择继续的人也推进到同一执行时间。

最终通关后的自动回收以 `T3+1` 开盘为统一终点。提前返程或战斗失败，只按当时已推进到的时点后的下一个可用执行报价回收，不偷偷拿完整终点给早退者结算。自动回收不计为主动退出行为。

战斗失败可以结束该局，但浏览器关闭不执行自动回收。恢复页面后从原状态继续。缺少必要报价时保留待结算状态，不用 0 或最后价悄悄替代；无效案例不能发布到正式池。

### 5.5 账本公式与示例

令 C 为现金，P 为同口径派生价格，q 为份额。提交金额 A 后先预留 A；执行时 `q = A / P_entry`。当前参考价值 `V_t = q × P_t`。回收比例 α 只作用于份额：`q_sell = α × q`；执行后 `cash += q_sell × P_exec`，`q -= q_sell`。

内部金额使用整数最小货币单位或固定精度十进制，份额保留足够精度；只在展示层四舍五入，不逐段反复截断。初始价格归一化不改变这些比例。

**人工机制算例，不是真实行情：**初始现金 100，投入 40，执行价 100，得到 0.4 份、现金 60。参考价到 90 时，份额参考价值为 36，总参考资产 96。选择收回一半，执行价为 88，卖出 0.2 份，到账 17.6；现金 77.6，剩余 0.2 份，按同一执行价总资产 95.2。之后花 20 升级，现金 57.6。若最终执行价 110，再回收 22，最终现金 79.6。

升级支出 20、战斗奖励和契约自身损益必须分栏：不能把购买升级后现金减少写成“亏了 20”，也不能用战斗奖励掩盖契约损失。

### 5.6 情报和计划

敌人当前意图、契约基本规则、已发生的当前余额、商品价格属于必要信息，免费提供。付费额外资料可以是更长历史、同期对照，或战斗之外的路线细节，但不能包含未来真实行情或准确预言。

P0 优先实现一份可选“历史档案”：4 金币打开更长历史与同期对照的可切换视图。不是只许看两张；愿意承担成本即可看完。可免费查看已经买过的同一份档案，重复点击不形成新证据。

玩家可在金币栏标记“希望留给补给的数额”，仅作本人可调整的计划。没有标记就不推断其内在底线；有标记也不能把后续改变解释为失信或控制力差。

## 6. 观察模型：先描述事实，再讨论用途

### 6.1 四层信息必须分开

| 层 | 内容 | 可以做什么 | 不能做什么 |
|---|---|---|---|
| L0 游戏事实 | 拿过／打过什么牌、战斗胜负、实际余额、可选项 | 战报、复盘、调试 | 直接转成现实人格 |
| L1 本局情境观察 | 在具体资源、信息和可行选项下做了什么 | 有限定条件的本局描述 | 宣称动机已被证实或具有稳定特征 |
| L2 用户自述与校准 | 本人预期、感受、理由、希望获得的帮助 | 与观察并列，调整解释与推荐 | 把自述当独立能力证明或客观极限 |
| L3 研究任务表现 | 在明确数据与任务中实际完成了什么 | 记录该任务的学习进度和帮助暴露 | 用战斗技巧补出金融知识能力 |

P0 不输出“真实交易类型已识别”。结果标题使用“本局旅程风格／本局资源安排”，可以附“与交易决策相关的线索”，但其下必须能展开依据和未知项。与主办方沟通时说明：这是一组可修正的产品画像，不是风险适当性评级。

### 6.2 需要明确禁止的翻译

| 看见的行为 | 允许的描述／其他解释 | 禁止的结论 |
|---|---|---|
| 拿了很多攻击牌 | 本局构筑偏向攻击组合；可能是掉落、敌人和组合收益所致 | 激进投资者、偏爱高风险证券 |
| 频繁叠护盾 | 在对应敌人阶段安排了防护；也可能为成长争取时间 | 稳健投资者、现实承受力低 |
| 使用过载 | 将已知行动成本挪到下一回合；可能是防护或斩杀 | 杠杆偏好、冲动借贷 |
| 使用跳费 | 本场牺牲当前动作增加后续容量 | 长期主义、价值投资能力 |
| 斩杀时用尽能量／过载 | 在当前规则下完成了战斗 | 没有留余地、风险控制差 |
| 走强敌路线 | 当时选了该挑战；需看血量、牌组、奖励与替代路线 | 爱赌、现实风险承受力高 |
| 参与金额很大 | 在该资源状态下投入了具体金额与比例 | 贪婪、激进人格 |
| 选择不参与契约 | 保留现金；可能要买牌、不理解、没兴趣或想专注战斗 | 保守、金融能力不足 |
| 亏后回收 | 减少了后续敞口；可能是新信息、购买需求或感受变化 | 扛不住、恐慌、不理性 |
| 亏后继续持有 | 保留了敞口；可能有计划，也可能只是没有操作 | 承受力强、纪律性好 |
| 打得好／金币多 | 本局通关或资源结果 | 会投资、研究能力强 |
| 买了档案 | 愿意在本次条件下支付该信息成本 | 已读懂、会核验、研究型人格 |
| 看完档案后不改操作 | 这次操作没有变化；信息可能与原判断一致或不相关 | 不接受证据、固执 |
| 快速点击、思考较久、退出页面 | 操作或设备层事实；P0 不用于画像 | 冲动、犹豫、恐惧 |

**这些不是结尾免责声明，而是规则引擎的输入白名单和测试要求。** 战斗牌标签不得成为金融风格规则的直接特征。

### 6.3 一条有效观察需要哪些上下文

每个可记录的经营决策保存一个“选择快照”：可用现金、契约份额与成本基准、生命与护盾、当前牌组／升级、节点、可走路线、实际展示过的信息、待执行指令、商店目录与价格、规则版本、有效选项及不能选的原因。

同时记录自己是否首次遇到该案例、是否看过结局、是否使用提示、是否在教程或演示模式。有前置计划时记录计划，但计划不作为道德承诺。

“存在两个按钮”不一定意味着两个选择都现实可行。无法支付、规则不懂、教程强制、唯一生存选项、已看过答案、只有一个可达节点等，要保留事实并标记解释受限。系统无法可靠判定“唯一合理选项”时，不冒充算出了最优策略；显示未知并减少推断。

### 6.4 P0 只观察三个主题

**J1：当前可用资源与暂时参与量的安排。** 记录在 N2 提交金额、现金占用、已知采购机会及本人补给计划；在 N4／N6 记录回收与实际购买。可以说明“这次投入后仍留下了能买两份补给的现金”，不能说明“他总会控制风险”。

**J2：为额外信息付出代价，以及信息之后的行动。** 记录额外资料是否可负担、是否真的展示、所含信息版本及后续动作。单纯打开不证明理解；只有研究任务中的实际操作与判断才能产生相关能力证据。

**J3：变化发生后的计划调整。** 记录契约状态、生命、购买需求、新信息和参与量变化；把事前计划与事后操作并列。没有对应计划不生成“违背计划”；有计划也不能仅因改动就评价好坏。

P0 没有多个资产，不能测分散；持有期限被固定，也不能认定用户偏好长线／短线。没有真实资金与事实资料，不能测现实承担能力。没有可辨识的新信息，不能认定改变行为是信息驱动。

### 6.5 规则是事实模板，不是人格打分器

| 规则 ID | 最低条件 | 输出及用途 |
|---|---|---|
| J1-01 | 已展示可用现金与参与选项，用户自主提交 | 记录参与金额／比例与剩余现金；只描述本次 |
| J1-02 | 存在本人明确的补给计划及当前目录 | 比较当前资源与计划、可支付物品；不评遵守好坏 |
| J1-03 | 玩家实际尝试的购买因现金不足未完成 | 可推荐资金安排练习；不推断是不懂还是有意取舍 |
| J2-01 | 额外资料可购买且实际展示 | 记录本次选择付费查看；不生成“已掌握查证” |
| J2-02 | 同一决策有明确的操作草案，资料展示前后都记录 | 描述计划是否改动，附资料和其他变化；不自动归因 |
| J3-01 | 新的已展示状态出现后，发生自主回收或保留 | 描述这次行动和当时约束；无情绪判断 |
| J3-02 | 有有效事前计划，实际操作具有可比条件 | 描述一致／不同；原因缺失时保留未知 |
| J0-00 | 未参与、数据不足、强制执行、无法比较等 | 显示“这部分暂未形成观察”，仍可继续游戏和任务 |

观察附 `eligible_opportunities` 与 `observed_choices`，未出现机会时分母为 0，不输出 0% 能力。重复点击不新增机会。一个契约的三次更新是同一条路径的相关观察，不能叫三个独立样本。

P0 可以给单次有内容的描述，但不输出稳定分类。P1 有不同新案例、足够可比机会后，才讨论“多个情境中出现了类似安排”，并保留相反证据。没有统计校准时不显示人格概率、置信度百分比或精确风险分数。

### 6.6 游戏战报与人物表达

战报可以热闹：展示关键组合、拿到的牌、击败的敌人、最精彩回合。**“借力连击流”是游戏构筑名，不是金融人格名。**

观察区域用一至两句具体事实表达，例如：“第一营地参与契约后，你仍留了 22 金币；中途出现损失时，你收回了一半，并用到账金币升级了卡牌。”再说明仍不知道原因。

可选风味称号只能来自明确事实，标题限定“本局”。P0 默认“雾城旅行者”，不要求每个人都有不同称号。不能为了卡面好看硬凑“进取型／防御型／冒险型”分类。

### 6.7 不过度推断，不等于只打印日志

观察的价值是帮助用户看懂取舍。系统可以把“付了什么、保留了什么、还可以做什么”组织成解释，例如：“你保留的现金支付了途中升级，这发生在契约可以回收之前。”这是由账本支持的局内事实，不是对人格的猜测，也不假设另一种选择下玩家仍会做完全相同的事。

玩家明确表示“我想留钱给途中补给”，且操作与之相符时，可以写“你说希望保留补给余地，这次的安排实现了这个目标”。如果不同情境中出现相似选择，可以呈现为“这些已发生的情境中出现了相似安排”，并同时列出差异；不能把相关观察换算成高置信的稳定特征。

推荐据此回答具体问题：怎样保留一项购买机会、怎样核查某份资料、怎样比较另一段历史。**有用的个性化，不以先给用户定一种交易人格为前提。**

## 7. 自我预期校准：放进同一趟旅程，不导演损失

### 7.1 新版与旧补丁的关系

旧补丁使用独立的“风浪试航”和独立账本。[P2] 本版不把它直接接在冒险外面再测一次，而是在同一局的自然准备节点留下预期，在自然发生的可比节点回看。沿用“感受与行动分开、事后不改写事前、不能测出现实上限”的原则，重新定义触发与事件。

这是更贴近主线的设计取舍，**不是声称更强的心理测量效度**。玩家已经获得喜欢的牌，不代表虚拟损失等价于真实投资损失。关于模拟体验改善风险理解的研究提供启发，但没有验证本游戏，更不支持用更强刺激制造所谓真实反应。[R3]

### 7.2 P0：一次可跳过的条件化预期

在 N2 完成购买并确定契约金额后、尚未展示未来片段前，给一个可展开的“留给下一营地的自己”。不单独强制跳页，不在战斗中提问。

示例条件：

> 假设到下一营地，这份契约的价值比最初投入少了 10%—20%；你仍有至少 10 金币能买一份补给，生命也至少剩一半。你预计自己会有多在意？届时更可能继续、收回一半，还是全部收回？

参与金额同时换算成金币，例如投入 40 对应减少 4—8 金币。这里说的是**契约部分相对投入的变化**，不是整个钱包减少了 10%—20%。损失区间是待验证的情境配置，不是心理量表阈值。

感受选项：不太在意／轻微／明显／强烈／说不清或不回答。行动预测可选继续／收回一半／全部收回／还不知道；允许只填写感受，跳过操作预测。整张预期卡也可跳过，不影响奖励、路线和任务资格。

文案明确：“这是预测，不是承诺。后来改变主意不扣分。”旧答案在实际作答前不展示，防止诱导保持一致。离开 N2 前若更改参与金额等配对基准，旧预期保留为已撤回、不用于配对；用户可重新确认并记录新预期，不覆盖旧记录。

### 7.3 只在匹配的自然节点形成对照

P0 目标节点固定为下一营地 N4、首次展示该段收盘参考值之后、下一个执行报价与后续结局之前。引擎检查：

- 首次玩该案例，预期发生在未来片段展示前；金额、份额口径与目标节点一致。
- 契约参考损失落入预先记录的区间；现金与生命等明确条件满足。
- 没有自动清算、失败救援、强制操作或未完成结算；玩家实际拥有操作选择。
- 没有已知目标变化、理解冲突或其他让对照失效的信号；无法确认的部分明确保留。

满足后，先记录现在的感受，再让玩家实际执行继续／收回一半／全部收回。原因可在操作后选填：感受比想象强／对后续判断改变／要买补给或卡牌／目标变了／只是试试／其他或不确定。

**真实损失未发生、幅度不匹配、生命已经告急或中途退出时，不生成 gap 结论。** 可保留当下感受与操作事实，写“条件不同，不能和原先的预测直接比较”。不要为了完成校准临时更换价格路径，或把没有匹配写成“校准失败”。

数值与条件匹配也不代表因果条件完全一致；之前的战斗、掉落与新信息仍可能影响反应。输出始终是本次对照，不声称差异由情绪单独造成。

### 7.4 两个轴独立输出

**感受轴：**在可比条件下，实际自报感受比预想更强／接近／更弱／缺少回答。等级只比较顺序，不计算差了几分、承受力百分比或实际亏损上限。

**行动轴：**事前倾向与当前自主操作一致／不同／缺少预测／条件不可比。行动变化不能代替感受变化，也不能反过来仅凭不适推定用户一定会退出。

必须支持以下正常结果：比预想难受却继续；不太难受但因购买需求回收；比预想轻松；没有差异；没有足够线索。一直持有不获得“更勇敢”的奖励，提前回收不扣研究能力。

### 7.5 对照卡与下次预期

> **事前的你：**在这类条件下，预计只是轻微在意，倾向继续。
> **这次的你：**在匹配的营地条件下，你报告明显在意，收回了一半。
> **已看到：**本次自报感受高于预期，操作也发生了变化。
> **仍不知道：**变化是否主要来自感受，以及这是否会出现在真实资金或其他情境中。

可选记录“经历后，下次准备怎样安排”。它生成新事件，不覆盖原预测。已知结局后重玩属于练习，不充当新的一次独立验证。

### 7.6 设计上接受“没有 gap”

首版可能有很多人没有可比损失，或不在意虚拟金币。这是数据限制，不是需要用冲击动画修补的体验缺陷。试玩报告分别统计：参与人数、填写预期人数、条件匹配人数、实际回应人数，不能只挑匹配且反差大的片段宣传。

校准不是通关必经之路，推荐也不以“发现你高估了自己”为前提。没有真实生活资料，现实财务承受能力仍然未评估。

## 8. 推荐：回答这局真正遇到的问题

### 8.1 先结束冒险，再给出下一步

结束页先显示战报和牌组，再提供一个推荐入口及“换个主题”。玩家可以直接再来一局，不要求完成学习任务才能继续游戏。结果不以“检测出缺陷”作为吸引点击的方式。

P0 必须做两个**真正可操作、内容不同**的任务：资金安排台与历史对照台。不靠两段改写文案宣称个性化。两者对所有人开放；画像决定默认入口和理由，不作为资格审查。

### 8.2 任务 D1：给旅程留出另一种余地

把本局已发生的契约路径、现金收入与实际采购时间放到一条时间线上。用户调整最初参与金额，或在允许节点调整回收比例，看哪些采购仍可支付、哪里失去余地。

这是**固定外部日程下的账本练习**：战斗奖励与采购需求是显式假设，不宣称改变投入后玩家还会打出同样的战斗结果。遇到第一次买不起的采购就标出并暂停该计划的后续计算，要求用户重新安排；不能悄悄跳过购买，再宣布这条路线也能通关。

实际交互至少包含：选择另一参与金额 → 更新现金／份额时间线 → 指出一项购买是否可支付 → 保存本人的新计划。不能只有滑条变化和一句推荐话术。

适合的理由示例：“你中途想升级，但当时大部分金币仍在契约中。这里可以试试另一种安排。”如果购买需求并未被观察到，只说“你可以比较不同安排”，不编造遗憾。

### 8.3 任务 D2：这一段不是全部

把用户的**固定操作日程**应用到另一个未在本局展示过的历史案例，或比较原案例与同期基准。先明示并锁定参与量、检查点和回收比例，再查看结果。

展示同口径的契约变化、现金可用性和持有部分的最大回撤，明确不同指标回答不同问题。用户可实际切换历史区间、打开对照、选择与数字对应的描述。

不把“继续／回收发生在某个时点”包装成适用于所有行情的策略：真实玩家在另一段数据里可能会改变行动，本任务只是固定日程的条件计算。研究结果不代表样本外有效性、适合投资或市场预测。

原版任务 A/B 的图表、基准对齐和时间边界思想可以复用；题目、指标和结论必须按新任务重新核验，不能只改标题。[P1：§5、§7]

### 8.4 路由与帮助

优先级：用户明确选择主题 > 用户明确提出的理解／帮助需求 > 本次有效校准或具体资金安排事件 > 已观察的信息探索兴趣 > 两个任务并列供选。

J1-03 等实际支付受限事件可优先 D1；有效校准中感受较预想强，可建议 D1 比较参与量，但不规定“应该投多少”；查看过额外历史、希望核查本次现象，可优先 D2。都没有时就让用户选，不从攻击牌数量兜底推断金融兴趣。

帮助方式默认采用中性、可切换的“给提示”，用户主动选择优先。战斗输赢、过载次数、人物称号不控制帮助档位。报告“没看懂”可以出现说明入口，但不锁定低等级内容。

研究任务完成记录只描述这一步实际做了什么。看过提示、答案或已知案例后重试，不能变成独立掌握证据；需要新的情境才可增加新的独立观察。任务可完成不等于通过心理测评。

### 8.5 两条可演示的差异路径

**路径甲：**使用借力连击牌组；在 N2 保留了可用金币，买了额外资料；中途按自己的采购计划回收一部分。战报写连击构筑，观察写本局信息与资金安排；默认提供 D2，理由指向已看过的历史资料。

**路径乙：**使用相同牌组和相同首场奖励；N2 参与较多，途中实际出现了一次买不起的升级，N4 回收后完成购买。默认提供 D1，直接重建那个购买节点。不能把乙叫“更激进的人”，更不能用甲乙的最终收益排名证明类型优劣。

这两条是模拟演示路径。反过来，也应能展示使用成长牌组的人与连击牌组的人做出相同经营安排，得到相同范围的经营观察。**游戏打法相同可以推荐不同；游戏打法不同也可以推荐相同。**

## 9. Panda Data 的实质作用与数据边界

### 9.1 哪些是真实，哪些是游戏

| 内容 | 来源与标注 |
|---|---|
| 契约历史价格比例、历史回撤、同期对照 | 获准使用的 Panda Data 数据及派生计算 |
| 敌人、伤害、金币价格、奖励、地图、牌池 | 本游戏设计的虚构规则 |
| 金币与历史序列的映射 | 简化的游戏结算，不是真实证券交易产品 |
| 人工账本算例、预设评委路径 | 明确标“机制示例／模拟演示” |
| 现实金融画像与承受能力 | 未验证／未评估，不由以上项目自动得到 |

不把指数走势直接装饰成怪物天气后宣称完成数据应用。数据应通过契约份额影响实际现金与采购空间，并进入后续可操作的研究任务。

### 9.2 案例池与选案

P0 目标为 3—6 个已核验案例，至少有可展示的不同变化路径；具体规模取决于数据与授权。每局开始固定案例 ID，不能根据玩家的预测、选牌、投入或当下情绪更换下一段。

可为教学与演示选择包含上行、回撤后恢复、持续回撤的案例，但必须标明这种选案参考了未来结果，**不能宣称它们是市场随机抽样，也不能从池内比例推算未来涨跌概率**。普通体验与专门演示种子区分；演示中的明显亏损不冒充普通用户必然遇到的情境。

不同路线使用相同的本局市场时钟。战斗随机、奖励随机和案例选择使用独立的种子流，防止一次多抽牌悄悄改变后续行情。

### 9.3 数据文件与执行口径

沿用离线计算、前端无密钥的思路，不重新承诺任何接口当前一定可用。[P3] 正式生成前再次核验可用接口、复权、分红、停牌、日历对齐及公开展示权限。

拟输出：`expedition_manifest.json`、每案起始历史文件、按阶段拆分的执行报价与展示片段、研究任务用对照文件。每份记录来源、接口、标的／基准、时间范围、选案规则、计算版本、授权状态、生成时间与文件哈希。

收盘用于营地观察，下一开盘用于执行；资产与基准使用相同端点和口径。不能用当前后复权／前复权序列就宣称严格的点时回测，也不能把价格变化自动称为含分红总回报。费用、滑点、市场冲击与成交限制在 P0 不完整建模，来源页须注明。

缺执行价、非正价格、日期错位、停牌或其他关键条件不满足的案例应排除并记录原因。不能前向填充成虚假的可成交报价。案例池有选择偏差，不用增加数量掩盖。

### 9.4 可见信息边界

初始包不含未来价和未来损益。订单锁定后才请求必要的下一报价，完成对应战斗后才加载该历史片段；不为了页面预加载，把完整未来数组交给观察函数或普通组件。

静态文件可被技术用户主动访问，这种分段是防止产品误用未来信息，不是防作弊或强保密。重复玩同一案例、主动选择已知演示种子时记录 `prior_exposure=true`，不计为新证据。

### 9.5 QuantSkills 与外部入口

只采用已经核验适用的研究方法或资源，说明具体用途与授权。P0 可以把它作为 D2 的时间边界、比较与复核方法参考；没有接入执行能力时写“方法参考”，不能写“已集成量化研究引擎”。实际数据接口、示例资源、尚未接入入口分开显示。

## 10. 页面与交互要求

### 10.1 游戏界面

战斗页首先让人读懂：敌人要做什么、我有什么牌、还能做几次动作。手机竖屏使用上方敌人与意图、中间简洁反馈、下方手牌；卡牌点击放大并可点选目标，不要求精准拖拽才能使用。

能量显示三件事：当前可用、容量、下回合锁定；成长牌预览强调“新增的是空格”。生命与现金稳定显示，契约价值折叠在独立账本中，不让全屏充满财务图表。

动画表现出牌顺序、连击与成长，支持减弱动效、跳过过长结算；不使用倒计时迫使交易，不靠报警音和红屏放大损失。不把保护性提示做成羞辱。

### 10.2 营地与路边补给

营地页同屏能看到自己的牌组摘要、可用现金和可购买项目。契约使用明确金额，不只写“投入一部分”。数据详情逐层展开，不让所有人先读统计说明才能继续。

路边补给只提供少量现金消费，不能回收契约；玩家可以直接进入战斗。是否有补给和回收限制在上一营地已告知。余额不足的商品不隐藏，标明差额，避免用户误以为这个机会根本不存在。

### 10.3 报告层级

默认战报不超过一屏半：本局结局、关键牌组组合、最多两条具体经营观察、一个推荐入口。详细依据放在展开区。校准只在有回答时显示独立区块，不填“承受力待解锁”的诱导槽位。

不强迫每一局给出动物、流派和金融称号三套分类。游戏称号与观察标题视觉分区，防止用户把“爆发流”误读成投资评级。

## 11. 实现结构、事件与版本

### 11.1 不为了重构先换技术栈

在现有 TypeScript／H5 工程内增加确定性游戏状态机、战斗结算和新页面即可。P0 不引入多智能体、在线 LLM 评分或复杂游戏引擎。是否换渲染框架由实际交互需要决定，不以换技术栈代替设计。

本次 README 显示原工程已有静态数据、事件、纯函数引擎与评委面板思路，但本 PRD 没有重新执行仓库测试；以下是迁移方案，不是可直接复用比例承诺。[P3]

```ts
// 建议模块边界，不是现有接口已经具有的能力。
reduceRun(state, action, visibleData, content, rngState) -> nextState
settleContract(ledger, order, permittedQuote) -> ledger
buildOpportunities(events, snapshots) -> opportunityRecords
observeRun(opportunityRecords, observationConfig) -> observations
compareSelfForecast(forecast, response, contexts) -> calibrationResult
recommendExploration(observations, statedNeeds, availableTasks) -> recommendation
```

`reduceRun` 负责真实可玩的世界；`observeRun` 只读取允许的机会快照，不能改变敌人、掉落、市场路径或价格。推荐不控制用户是否有资格通关或继续玩。报告使用模板，无需 LLM 才能生成。

### 11.2 事件与快照

所有事件带 `run_id`、递增序号、节点、版本、来源（真实操作／演示／分叉）、局内阶段和快照 ID。牌与订单使用唯一实例 ID；重复提交用幂等键拒绝。

| 类别 | 建议事件 | 用途 |
|---|---|---|
| 游戏 | `run_started`、`card_played`、`turn_ended`、`battle_resolved`、`reward_offered`、`reward_selected` | 游戏重放和战报，不直接推金融类型 |
| 机会 | `choice_presented`、`option_unavailable`、`route_selected`、`shop_opened` | 记录真实可选集合与约束 |
| 经营 | `purchase_attempted`、`purchase_completed`、`reserve_plan_set`、`contract_order_submitted`、`contract_order_executed` | 实际资源安排与账本 |

## 12. 评委面板：反事实需要尊重后续依赖

### 12.1 三种模式明确区分

**真实回放：**展示真实操作和当时可见信息，不改变原记录。

**规则检查：**在冻结的局面中修改一个允许字段，检验观察／推荐函数是否遵守边界，例如只改卡牌美术或游戏构筑标签，不改变经营观察。

**游戏分叉：**从某个决策前的状态重放，改参与量、路线或卡牌，然后重新演算游戏状态。分叉明确标“模拟”；因资源、血量或可选项变化而不再成立的后续动作必须停止、重新选择或由已声明的机器人策略执行。不能沿用原人的后续选择、感受和理由，假装真实用户在新局面也会这么做。

### 12.2 原版反例需要改变范围

v0.3 可以整体替换事后收益而保持能力画像不变。[P1：§9] 新版中，**已经看见的损失会影响现金和后续机会**，所以不能再要求“替换所有走势，整局观察和推荐逐字不变”。

正确的约束是：改变某决策时尚未展示的未来，不回写这个决策当时的判断与依据；但未来真的揭晓后，新的资源状态、玩家新行为和相应观察可以不同。面板必须显示分叉发生在哪个时间边界。

### 12.3 P0 面板必备

加载当前局或两条预设路径；查看“局面—可选项—动作—依据—推荐”；在合法节点分叉；解释为什么变与为什么不变。最低可编辑对象包括：契约参与量、查看资料、营地回收选项、可比情境中的预期回答。

改变已展示价格、现金、血量或其他匹配条件后，原校准反应变成不适用，不能保留并重新包装为“这个人更不抗跌”。模拟补填的反应始终属于模拟数据。

不能通过编辑面板清除提示或重复案例暴露历史，使一条记录伪装成独立能力证据。所有面板输出与正式功能走同一规则函数，不硬编码演示结论。

### 13.2 按验证门槛推进，而不是按页面数量推进

**G0：只做两场能玩的战斗。** 基础牌、过载、成长、第一次奖励和第二场。没有画像也要能玩。试玩者拿到牌后仍不想继续，先改战斗和奖励，不增加观察维度。

**G1：先打通最小赛题闭环。** 两场战斗之间接入一次经营取舍、一次短研究操作、一条有依据的观察、可操作的推荐及任务后的画像更新。用相同游戏行为、不同研究表现证明后续引导有合理差异，再扩展章节。

**G2：形成一小章与有实际影响的经营。** 加入分叉、升级、最终战、契约、路边现金机会和营地结算。验证两种构筑与混合打法、参与量或历史变化确实能改变一项购买／行动；排查明显退化策略，仍保证不参与契约也能通关。

**G3：补齐观察、校准与评委验证。** 在 G1 已完成闭环上扩展 J1—J3、知识观察、兴趣与学习需求、可选校准、D1／D2 和面板。不为了填画像而反过来改变敌人、牌池或市场。

**G4：试玩与交付。** 检查真实手机体验、数据许可、素材声明、运行说明、演示和状态标注。指标是验证门槛，不是对未来完成时间的承诺。

| 原资产 | 处理 |
|---|---|

### 13.4 做不完时砍什么

优先砍：额外美术、分享图导出、更多案例、复杂地图、遗物、多人物称号。可以减少战斗内容和选牌数量，但至少保留两场之间的成长与一次组合兑现。

不能砍掉：真实出牌与胜负、奖励对牌组的影响、资源账本正确性、行情／示例标注、错误人格映射的禁令、至少两种能操作的推荐任务、合法反事实与来源区分。

没有授权或真实数据就明确显示示例模式，承认 Panda Data 实际应用尚未完成；不让示例悄悄进入正式数据展示。没有可比校准情境就显示未形成对照，不为了演示顺利伪造情绪。

## 14. 验收：玩法、计算、观察各测各的

### 14.1 游戏性与平衡的首轮检查

1. 关闭报告和画像后，首次试玩者仍能完成战斗、理解奖励并愿意进入下一场。记录具体原因，不只问“好玩吗”。
2. 能演示至少一次连击效果大于单牌相加的组合，以及一次成长增加后续可执行动作的回合；不是只展示更大的静态数字。
3. 过载既可能用于斩杀也可能用于防护；成长有合适与不合适的时机。没有“这类牌必然代表某种人”的 UI。
4. 在固定的多个种子上，检查全攻、全防、见成长就成长、永远不拿牌、永远选强敌等简单策略。发现某个策略几乎无条件占优时，作为平衡问题处理，不把其他玩家评价为更差的人。
5. 无需参与契约、无需回答校准、无需完成研究任务，也存在可玩的完整路线。只有游戏本身的生命和目标条件决定本局结局。

### 14.2 机制和账本自动用例

| ID | 输入／改动 | 必须得到的结果 |
|---|---|---|
| T01 | 容量 3，当前能量 3，打借火 | 当前能量 5，待过载 2；无其他变化时下回合可用 1，再下一回合恢复 3 |
| T02 | 容量 3，打引根 | 支付 2 后当前剩 1，容量 4；新增空格不立即补能量；下回合 4 |
| T03 | 借火后同回合引根 | 当前能量从 3→5→3，容量 4，待过载 2；下回合可用 2 |
| T04 | 待过载加新牌过载大于容量 | 拒绝打出，不扣费用、不发生伤害或抽牌 |
| T05 | 过载牌造成斩杀 | 敌人不再行动；本场待过载清空，不加下一场惩罚，不贴金融标签 |
| T06 | 余烬后连刃，均未升级 | 三段各 5，共 15；反向顺序不回溯加伤害 |

### 14.3 防误判与校准用例

| ID | 场景 | 预期 |
|---|---|---|
| T13 | 相同经营事实，把游戏构筑标签从连击改成长 | 经营观察、现实承受能力字段不变；只改战报展示 |
| T14 | 没有提供某卡、买不起档案、只有一条可走路线 | 不能记录为主动拒绝或偏好；保留对应机会限制 |

| T26 | D1 替换参与量导致一次购买不可支付 | 标出并停止原采购计划；不假装玩家仍按原战斗过程获胜 |

### 14.4 真实试玩与研究效度不是同一项验收

先找少量真实玩家检验：能否理解过载与空容量、是否出现“想试下一张”的时刻、是否理解现金和份额不同、是否真的在意经营选择、推荐是否回答了刚才的问题。人数与结果如实记录，不把几个正面反馈写成心理学验证。

单独记录卡牌游戏熟悉度和是否已看过案例，允许自愿回答。比较不同熟悉度是否造成操作门槛；不能把“玩过炉石的人更会组合”当作金融知识优势。

测评有效性需要后续另行研究，包括跨新情境的一致性、不同任务间关系、与独立事实资料的对应，以及推荐是否帮助用户行动。当前自动测试只证明实现符合规则，不证明这些规则识别了真实交易类型。

## 15. 隐私、告知与提交

开局提供清楚的选择：“开始并生成本局观察”或“只玩游戏”。只玩游戏时仍保存继续游玩所需状态，但不运行人物推断，不收集预期、感受和原因。启用观察时说明用途与本地保存方式；默认不上传到服务端。

可随时撤销观察，删除校准与解释历史，保留必要游戏进度；另提供清除全部本地记录。保存期限在 UI 中说明，首版建议过期清理 30 天以上的本局观察，具体实现与文案保持一致。操作耗时可以用于经同意的体验测试，不能用于推断人格。

分享卡默认只含游戏结局与构筑表现，不含金币、投入、情绪、原因或原始决策。导出完整 JSON 必须主动确认，演示真实玩家记录要另得同意。数据账号、密钥、原始受限行情不进入前端或公开日志。

交付包包含：手机可用 H5、代码与运行说明、实际实现范围、两条差异路径、可操作的推荐和评委面板、3—5 分钟演示视频、数据和素材来源、AI／第三方组件说明。不要把新 PRD 写完等同于功能已完成。比赛提交时间和数据公开权限按最终通知核验，不在本文猜测。

建议视频先展示一场战斗中的真实组合和一次拿牌成长，再展示资源决策如何改变购买，最后展示观察边界、不同推荐与面板检查。不要用前三分钟解释规则编号，最后才让评委看见游戏。

## 16. 尚待原型回答的问题

**组合是否足够好玩。** 14 种牌只是首轮试验规模。若组合感弱，先改牌之间的关系和奖励节奏，不靠更多卡牌名称掩盖。

**短战斗是否给跳费回本机会。** 成长若总来不及兑现，需要调整敌人节奏、初始牌组或成长费用；但也不能把所有敌人做成“先成长再打”的固定解。

**契约结果是否影响玩法而不过度主宰。** 真实历史波动可能对小额金币影响过小，也可能造成一局差距过大。先调整价格、起始资金、路径长度和案例覆盖；不能偷偷放大价格收益，再标成未经改造的真实结果。核心战斗必须在不同经济结果下仍有可玩的解法。

**付费资料到底有无价值。** 用户是否能用它完成自己的决策，还是为了猜测系统偏好才买？必要信息免费、额外信息付费这一边界需要试玩，不能靠“购买率高”证明设计正确。

**有多少校准真正可比。** 匹配很少时可减少此模块的曝光和宣传，先保留真实观察；不要为了提高完成率放宽口径，导致不同损失和不同局势被强行配对。

**画像能否带来可感知的下一步。** 如果默认推荐改变了，但玩家只看到两段类似介绍，说明闭环没有成立；应修任务，不再加人格维度。

以上未确认的问题都属于设计风险，不是要求开发先假装已有答案。

## 17. v0.4.1 赛题对齐修订与 MVP 验收

本节把“认识自己”落到知识、研究习惯、兴趣和学习需求的可观察操作。赛题允许选择部分维度深入；本 MVP 只覆盖下列很小的研究能力，不宣称全面测量量化水平。玩法与冒险结构仍按前文实施，不用几十道问卷取代游戏。

### 17.1 能力与研究过程

| 观察 | 有效任务操作 | 可输出的结论 | 不可输出的结论 |
|---|---|---|---|
| K1 同期比较 | 在同一日期口径下比较资产与基准，并选择与数字相符的描述 | 本任务独立完成／提示后完成／结论待确认／未观察 | 已经掌握所有量化研究 |
| K2 时间与证据边界 | 固定操作日程后，查看另一历史片段，区分本段结果、不同片段差异与未来预测 | 本任务识别了样本边界，或需要进一步确认 | 策略有效、未来必然盈利 |
| K3 可用现金与参考价值 | 在 D1 标出采购节点是否可支付，调整计划并重新验证 | 本任务区分了可用现金与待回收价值 | 现实风险承担能力或理财水平 |
| H1 研究过程 | 先留下待核查判断，选择历史／基准资料，查看后保留或修正判断并选理由 | 本次如何核查与更新判断，附机会和证据 | 买过资料等于会研究，改判总比坚持好 |

每次任务保存案例、题目版本、初答、实际展示的数据、提示／答案暴露、最终选择、原因与证据 ID。判定由数据计算，不由 UI 传入一个可伪造的正确标志。同题重试不新增独立证据。不同未见案例的矛盾表现并列保留，状态为“不同情境表现不同”。正确的单次独立操作只写本任务完成，不宣称稳定掌握。

N2／N4 可展开一个短研究操作，让用户在结束冒险前看到早期价值。跳过不会扣分，也不影响战斗或任务资格。研究题目可以使用已购买的资料，或在任务中免费提供完成所必需的数据；帮助费用不能成为能力判定的混杂因素。

### 17.2 兴趣、目标与帮助

允许用户明确选择当前想探索“资金安排”“历史比较”或“验证一个想法”，可跳过、修改。记录为本人的当前目标，不当作稳定兴趣。购买历史档案只提供本次探索线索；不将构筑、输赢或操作快慢映射成金融兴趣。

分别记录：当前目标；具体知识观察；需要进一步练习的步骤；主动选择的帮助方式（自主／提示／分步）。默认推荐用目标和已观察任务表现匹配内容及引导，用户选择始终可覆盖默认；不设置人格资格门槛。

知识未观察时提供一个可选起点，不写成能力不足。一次提示请求不是低能力证明。只有任务中实际出现的理解困难可以支持“这一步可先给说明”的建议，并写明本次依据。

### 17.3 两个任务与更新闭环

D1 保留资金安排台：金额／回收比例调整 → 显示现金与份额时间线 → 判断一个采购是否可付 → 保存新计划。无法支付时停止原采购计划后续，不伪装可按原战斗过程通关。K3 通过实际判断产生，滑动金额本身不是能力证据。

D2 保留历史对照台：先留下可核查判断和固定日程 → 选择同期基准或新历史片段 → 查看同口径结果 → 提交描述与理由。K1／K2／H1 各有明确判据。两类任务所有人可进入，帮助可随时切换。

每次提交后必须显示“此前观察 → 新增依据 → 现在观察 → 下一步为何变化／为何不变”。更新只影响有证据的维度。带提示完成后推荐新情境练习；新情境独立完成后可默认更少帮助；冲突时显示差异并提供核查入口。避免无限自动增加难度或把任务完成等同于能力认证。

结构化输出在原有旅程观察、校准、推荐之外增加 `knowledge_observations`、`research_process`、`stated_interest`、`learning_needs`、`help_preference`、`profile_changes`。所有推断项均能追踪证据、来源、范围和未知项。

### 17.4 可解释、可修正和评委追问

观察卡提供“补充我的原因”：留钱升级／没看懂规则／暂时不感兴趣／我想自主尝试／其他或不确定。本人补充不篡改原事件，而以新事件修正解释与推荐。用户自述不能替代已发生的操作，也不能强迫用户接受系统解释。

评委面板同时支持：真实记录回放；关键经营决策的合法分叉；补充目标／理由；不同研究表现与帮助暴露的模拟对比。全部调用正式函数，分叉及预设数据始终标为模拟。变更历史选择后失效的后续动作与反应不能继续作为真实证据。可退回真实记录；原存档不被面板覆盖。

### 17.5 MVP 开发和交付约束

首个 demo 保留 14 种卡、4 场战斗（教学、两次路线选择、Boss）、选牌、商店与升级、一个真实历史派生契约、两个研究任务和评委面板。数据案例优先复用仓库已发布且来源可追溯的 Panda Data 快照，至少支持两个不同历史情境；若不足 3—6 案，在实现范围中明确标示，不能编造来源。未来片段按阶段加载；标注只防误用，不声称静态文件能防作弊。

主线美术使用本次 GPT Image 生成的原创晨光小城插画，或具有可核查授权的开放素材，记录生成提示／来源／用途。卡牌机制、按钮和关键数值使用清晰的 HTML/CSS 与文字，不把必要信息写死在图片内。手机触控可操作，支持减弱动效。

保留 v0.3 可运行入口；v0.4 使用独立存档。正常游玩、模拟演示和评委分叉有明确来源。观察可撤销，清除数据实际生效；只玩游戏不采集知识、兴趣、感受或理由。MVP 无需生产账户、在线 AI 评分或付费服务。

QuantSkills 如采用具体资源，记录已核验的资源名称、出处和用途；未采用时明确披露，不把一般方法包装成官方集成。Panda Data 的来源、原始时间端点、下一可用执行报价、简化与选择偏差须可在 demo 查看。

### 17.7 上线后校准覆盖与重叠资料修订

已核查首批三案在 N4 的变化均不落入预先声明的 10%–20% 损失区间。保留这个事实，不放宽事后配对条件。新增一个真实历史案例：000063.SZ、2025-02-07 收盘为 T0，下一交易日入场、T0 后第20交易日观察。该案是为覆盖指定情境而后验选取，必须披露选案偏差、前复权和成交简化；不能用其比例推算市场风险或保证出现某种感受。

新增案与原 lantern-c 同标的且有历史交叠，必须关联暴露记录，不因新案例 ID 宣称未见。普通新局在未见候选中独立选案，与战斗随机分开，开局后冻结；已有存档不得换案。后续因研究或演示看过相关资料，只影响之后的独立性，不抹掉此前成立的真实任务证据。用户主动补充“我在本局之前看过这个案例”则属于先验更正，由正式规则重新评估有关观察并展示变化，保留原任务事实及声明依据。

初始历史改为逐案例加载。新目录 `manifest.v2.json` 只有元数据；选择固定后仅请求该案 `initial/<case>.json`。不得把所有案例起始历史一起预取，因为新案的过去可能是另一案的未来。保留旧目录及旧案文件供已上线旧客户端使用；新文件采用独立完整性清单。

评委可打开一段由正式引擎及真实阶段数据生成的 N4 模拟局，分别调整“假设的事前感受／行动”和“假设的当下感受／行动”，比较是否匹配及两个轴为何变化。页面始终区分真实历史报价、模拟游戏路径和可编辑假设，不把输入称为用户真实感受；不写入真实局的画像。原有关键参与量、资料与回收分叉保持可用。

新增验收：T36 新案可经合法动作达到匹配条件且失败按真实下一开盘退出；T37 新客户端只取当前案例的起始历史，不收到重叠案例未来；T38 看过C后D不能算新独立情境，普通后续观看不追溯抹去已成立证据；T39 主动先验更正保留原记录并解释观察变化；T40 评委双轴模拟与真实存档隔离，旧版本数据文件兼容。

### 17.8 任务帮助兑现与战斗选择可读性

帮助不能只出现在推荐文案里。进入D1时依据K3、进入D2时依据K1/K2计算当前任务建议，明确显示来源与理由。本人明确选择提示或分步时，在题目可用后展示相应内容；系统推断的建议供本人选择，不自动把未观察用户计为依赖提示。只有帮助内容实际在当前任务展示后才记录暴露；仅选偏好、后台渲染或被弹窗遮挡不能算看过。切回自主尝试可以收起帮助，但不能抹去已经看过的事实。

提交后的下一步必须可操作：可直接切换另一任务，或进入尚未见过且不泄露当前游戏未来的案例。案例池耗尽时明确称为复习，不把同题或关联窗口重新包装成独立情境。目标、知识与帮助的变化原因继续分别解释。

选中战斗卡牌时，按当前公开状态解释本张牌实际可造成的伤害、破盾、护盾和剩余能量；组合增伤应可见。过载说明下一回合的影响，成长说明增加空容量；斩杀后说明战斗已结束，不让用户误以为仍要承受下一次攻击。预览用正式规则，但不修改真实局、不执行真实观察、不透露尚未抽到的牌或后续随机结果。弹窗支持键盘循环、Escape关闭和焦点返回入口，背景不能被误操作。

新增验收：T41 显式帮助偏好在D1/D2兑现且仅实际展示计暴露；T42 切回自主、刷新或改计划不消除已看帮助；T43 提交后可到达另一任务或真实未见案例，耗尽清楚标为复习；T44 卡牌预览与正式动作一致且原状态与隐藏抽牌不泄露；T45 弹窗键盘操作不落到背景，关闭返回入口。

### 17.9 简短战报与可演示交付

落实§10.3的短报告：默认视图先显示当前阶段或结局、至多三条由事件证明的游戏亮点、最多两条经营观察、简短知识状态和一个可操作的主任务入口。另一任务、完整牌组与账本、研究过程、详细依据、预期对照及目标/帮助设置继续可达，但不默认把所有内容铺开。手机常用视口的默认内容以约一屏半为目标；展开后长度不限，不截断关键文字换取视觉达标。

游戏亮点只描述实际打出的组合、已击败对手和获得的奖励，不把持有卡牌当作已经用过，不把失败或提前返程写成通关，也不进入交易观察或知识评价。旧记录缺少伤害明细时不重建未知值；所有亮点保留事件和真实/模拟来源。

数据说明应在界面中列出PandaData使用的接口、当前案例标的与起始时点、基准、复权和归一化口径；以实际已发生的行情事件串起参考报价与下一开盘成交日期。不能为了说明数据而预先请求当前局未揭晓的未来。

提供3—5分钟功能演示录屏及可复现步骤，覆盖战斗与成长、研究操作、任务后更新、评委改变关键选择和数据来源。章节明确录屏是自动化操作示范，不是外部真人试玩；模拟路径保留界面来源标识。只使用本次演示生成的本地记录，不展示他人记录。

新增验收：T46 报告默认短且全部既有能力仍可达；T47 游戏亮点有实际事件依据、缺字段时保留未知、不会改变研究输出；T48 主案独立但次案已见时分别解释K1/K2，不笼统降级整次研究；T49 数据说明可查已发生时点而不请求未来；T50 录屏长度、章节、来源标识与可复现操作均可核验。

### 17.10 牌区与回合变化可查看

战斗中可点击抽牌、弃牌和消耗区计数，查看只读组成，并切换手牌或完整牌组。卡牌按定义和升级状态分组、固定排序；说明这不是抽取顺序，不展示下一张、实例编号、牌堆顺序或随机状态。抽牌组成可由本局完整牌组减去已知手/弃/消耗区推得；数据不完整时明确标示未知，不补造缺牌。查看和切换不会出牌、推进随机数、改选牌或写研究观察。

手牌明确区分卡牌自身“保留至打出”和候机赋予的“本次结束后保留”；一次性保留跨过本次回合结束后即取消，消耗牌本场不再抽到但下一场回到牌组。换回合后的能量说明使用该回合实际开始事件，分别显示恢复值、已结算过载与当前剩余能量，不能把借火临时能量当成容量或本回合恢复值。旧存档没有对应事件时不推算确定数值。

新增验收：T51 牌区计数与正式状态一致，排列/随机种子变化不会改变公开分组；T52 查看/切换/关闭保留选牌和存档，不产生游戏或研究动作；T53 临时/永久保留和本场消耗语义正确，跨回合/跨战斗按规则变化；T54 恢复能量、当前能量、已结算与待结算过载互不混淆；T55 手机弹窗可滚动、键盘可退出，关闭后返回原操作。

### 17.11 推荐理由与当前资源分别说明

保持§8.4的用户目标、本人需求及经营事实优先级；不为了制造“变化”而在一次答对后强行换主题。任务完成后分别说明新增了什么观察、主推荐为何变化或维持、帮助方式为何变化或维持。前后比较只使用实际捕获的推荐状态，旧记录缺快照时不补造历史推荐。

推荐还要说明目前能实际提供的内容：D1使用本局已发生报价及采购的账本，或明确为不增加独立观察的机制示例；D2区分未见片段、已有锁题可继续、只有已见资料可复习，以及目录未加载。案例是否可用不等于能力是否不足，未见也不保证本次提交能新增独立证据；关联窗口不按多个独立情境计数。没有可用未见案例时，不无条件承诺“继续新情境”。

已有存档遇到案例目录加载失败时，任务内可重试目录，保留游戏进度和已锁题的原始先验。目录缺失不得显示成“所有案例已看完”。研究任务页继续显式标记预设模拟或分叉来源，只玩模式保持中性练习且不引用旧画像。

新增验收：T56 资源说明与D1实际来源、D2候选/锁题一致；T57 未见池耗尽只提供复习，不伪造新情境；T58 明确目标或经营触发导致推荐维持时有可追踪说明；T59 目录失败可在任务内重试且不丢存档/原题；T60 模拟/分叉来源延续至任务页，只玩不使用旧观察。

### 17.12 启动反馈与安全恢复

页面主 HTML 已送达后，等待入口及界面加载时必须有可读的启动状态；入口脚本、动态 UI 模块、关键 CSS 或初始化失败时，不得留下无说明的空白页，应显示可理解的兜底提示及重试方式。关键素材失败时应有可见反馈或可操作的替代内容，非关键图片和字体失败也不能让必要文字或操作消失。基础提示不依赖发生故障的界面模块；禁用 JavaScript 时仍可阅读启用说明和浏览器刷新指引。首次请求连主 HTML 都未收到时由浏览器报告网络错误，本要求不承诺网站离线可运行或能消除所有访问失败。

加载缓慢时可提示继续等待或刷新，但超时提示不是终止加载：只要原请求随后成功，界面仍应正常显示，并移除启动兜底，不重复挂载或让旧定时器重新盖住界面。只有界面真正渲染且关键样式就绪后才撤去兜底；脚本成功不能掩盖关键 CSS 失败，错误提示也不得假称已经知道具体原因。

重试采用保留当前完整 URL 的刷新，路径、查询参数和片段均不得被丢弃，包括 `?legacy=1` 及部署子路径。启动、等待、失败和重试本身不自动清除游戏存档或以新局覆盖原进度，不重置随机流或替用户开始新局，也不新增游戏选择、帮助暴露、研究观察或评分；既有用户已知的观察保留期限规则不因恢复流程改变。旧版入口和旧版独立存档继续可用，出现启动问题时同样能看到提示。

问题复现依据：拦截修复前版本的 UI 资源时，曾观察到页面正文文本为空、`#app` 的子元素为零。该现象说明原路径存在空白页问题，不能作为修复后验收通过的证据。

本节属于对完成度与完整体验的交付要求及待执行验收，不能作为已完成验证、取得评分或真实用户已成功访问的声明。

| ID | 场景 | 待验收要求 |
|---|---|---|
| T61 | 主 HTML 已送达，入口脚本、动态 UI 模块或关键 CSS 加载失败／初始化异常 | 视觉和键盘用户都能获得可理解的兜底反馈与重试方式，不能只呈现空白页；关键素材不可用时可见反馈或可操作替代 |

### 17.13 公开敌人节奏与路线选择

为落实 §4.7 的可规划战斗，路线选择应展示各敌人的生命上限、既定奖励及开局前三个敌方阶段的行动。战斗中保留当前意图，并提供只读入口查看当前阶段及后续两次行动；当前意图以正式战斗状态为准，后续计划与路线信息均来自同一套正式敌人规则，不复制另一套数值。后续行动说明为“战斗继续时的固定计划”，不是保证一定发生：提前击败敌人或玩家失败都会结束本场，攻击数值也不是忽略玩家护盾后的必然生命损失。

依 §4.7，教学门卫不增长；其他敌人从第 10 个敌方阶段起，每经过一个阶段累计攻击加成增加 2，包括获得护盾的阶段，但加成只作用于攻击数值，不能加到获得的护盾上。预览必须按所展示的每个阶段计算，不得把当前加成机械地复制到后续阶段，也不得更改战斗数值或根据画像调整敌人。

查看、展开和关闭节奏仅呈现已公开的固定规则，不推进战斗或随机流，不改变路线、手牌、保留目标或存档，也不创建游戏选择、帮助暴露、研究观察或金融推荐依据。不得借节奏展示泄露抽牌顺序、随机状态或尚未揭晓的历史行情。手机默认布局保持紧凑，当前意图和查看入口易找，较长节奏说明可由用户展开；旅行者图片在容器内等比显示，不拉伸变形或裁切角色。

## 附录 A：开发与评审时的一页原则

> 战斗的目的是好玩，经营的目的是让选择有后果，观察的目的是提供有依据的下一步。
>
> 不把过载当现实杠杆，不把跳费当价值投资，不把护甲当低承受力，不把斩杀当缺乏节制。
>
> 先看玩家实际有哪些选择，再看他选了什么。没有可选机会，不输出偏好；没有新情境，不增加独立证据。
>
> 收益可以影响下一步能买什么，但不决定这个人是否聪明。改变计划可以合理，坚持也可能合理。
>
> 感受来自自报，操作来自事件，动机可能未知，现实财务承受能力没有被评估。
>
> 同一局里可以既喜欢爆发、又留足现金；可以既会查证据、又低估自己的感受；不同维度不必拼成一个整齐的人格。
>
> 关掉画像，玩家仍然想打下一场；打开画像，能看懂依据，并真的开始一个相关任务。两件事都成立，才算这次重构成功。
