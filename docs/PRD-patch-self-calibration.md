# 《下一张牌》PRD v0.3 增量补丁：自我预期校准

**适用基线：**用户提供的 `PRDv0.3.md`。本文仅列新增内容、局部替换文本与联动要求，不是全量 PRD；未列出的原规则继续有效。

**增补目标：**让用户先预测自己面对一段模拟损失时的感受与行动，再与体验中的报告和选择对照，发现“我以为自己会怎样”与“这次实际怎样”之间的差异，并完成一次可操作的计划调整。

**版本约定：**原能力规则继续使用 `rules_version=v0.3`；新增模块单独使用 `calibration_rules_version=self-calibration.v0.1`，下文规则编号以 `SC-` 开头。正式合并时可统一升级产品版本，但不能把旧规则编号悄悄赋予新含义。

**规格状态：**新增内容是本次产品设计，不是原 v0.3 已有功能，也不是已经验证的心理测评。文中的 100／30／24／94 等数值为机制示例；正式情境必须由实际获准使用的数据生成，不能标成已经取得的 Panda Data 结果。本文不修改、复核或重新声明原文中的接口可用性。

## 1. 对 §1 的增量：目标、术语与边界

### 1.1 在“首版理解的方面”表末追加

| 方面 | 类型 | 改变什么 |
|---|---|---|
| 事前预计的感受／行动，与经历同一节点时的报告／选择是否一致 | 自我预期校准：情境内描述，不是能力、人格或现实风险等级 | 是否建议读账本、比较不同模拟参与量、回顾判断改变的依据；不影响研究任务 A/B 的资格 |

### 1.2 将原 §1 最后一段替换为

> 不评定现实投资风险等级，不承诺识别稳定人格，不提供买卖建议。“行动习惯”仍只描述本局选择。新增“自我预期校准”观察用户对特定虚拟情境的事前预期与当下反应，不把一次模拟体验转换成现实亏损承受上限，也不据此认定用户具有稳定的高／低承受力。
>
> 现实中损失是否影响必要支出、债务或既定资金用途，需要独立的事实资料；P0 不收集和判断这些资料，统一标明“现实财务承受能力未评估”。游戏中平静、坚持或退出，都不能代替这项评估。

### 1.3 三个概念不得合并

- **现实约束：**损失会不会影响现实生活与资金用途。本补丁不评估。
- **事前预期：**尚未观看本段过程时，用户对一个明确节点的感受和行动所作的预测。
- **本次反应：**到达该节点、尚未看到后续结局时，用户报告的感受与实际作出的模拟操作。

首版输出的是后两者的对照。感受来自自我报告，操作是可观察行为；二者均不能被称为“已经测出的真实心理极限”。

## 2. 插入 §2.1：可跳过的「风浪试航」

### 2.1 入口与范围

第一幕结束仍立即给出初步人物卡，并保留“进入研究任务”“继续第二幕”。新增同级入口：

> **风浪试航：给未来的自己留一张牌。**
> 看见数字时的想象，和经历过程后的感受，会一样吗？

用户可跳过、暂停、返回原流程。拒绝参加不生成负面判断；已有方法卡、画像和任务资格不受影响。第二幕或任务完成后也可进入同一入口，但已看过的情境只能记为练习。

P0 只做 **1 个新情境、1 个对照节点、1 次当下操作**。以约 60—90 秒为体验设计目标，需试玩核验，不设强制倒计时，不承诺全部流程仍在五分钟内结束。

### 2.2 独立账本与告知

试航账本独立于 R1—R6：示例起始 100 颗松果，其中 30 颗随本段走势变化，70 颗保留。主线累计松果不转入、不扣除，校准账本也不回写主线。

进入前明确告知：

> 这里使用不能兑换现金的虚拟松果。本段是事先选定、包含松果减少的教学情境，不是随机市场抽样，也不预测未来。我们会先展示一个节点摘要，再让你经历到达它的过程。你可以随时退出，退出不代表能力或承受力低。

P0 不设现金、奖品、付费重试、扣除已获得奖励或损失学习权限等代价，不靠羞辱、倒计时、报警音或强刺激制造“不舒服”。行动不是考题，没有“坚持才算过关”。

### 2.3 流程与交互

| 步骤 | 用户看到／做什么 | 关键约束 |
|---|---|---|
| ① 看节点摘要 | 显示起始账本、参与量、将比较的节点、剩余区间与操作规则 | 此时不加载完整过程和最终结局；摘要是明确披露的情境信息 |
| ② 留预期卡 | 预测到该节点时的感受，并选择自己届时倾向的操作 | 是预测，不是承诺；不奖励与预测保持一致 |
| ③ 经历过程 | 走势逐段展开，账本跟随变化；可暂停或退出整个体验 | P0 在指定节点前不提供中途调节参与量，保持账本可比；退出始终可用 |
| ④ 记当下反应 | 到达节点后，先报告现在的感受，再实际选择继续／收回一半／全部收回 | 后续结局未展示；不显示旧答案或系统解读来诱导作答 |
| ⑤ 补充原因 | 一页可跳过的补充：为何改变、是否在意本次变化 | 是自述，不是因果证明；不能单独升级任何能力观察 |
| ⑥ 并排回顾 | 展示事前与当下的感受、操作及限定条件 | 差异可以更强、更轻、相同或未知；不强迫产生反差 |
| ⑦ 可选看后续／再想一次 | 看自己选择对模拟账本的影响；可记录对下次的新预期，并进入校准练习 | 新预期不覆盖原预测；最终盈亏不反向改写刚才的校准结论 |

**预期卡示例，仅用于说明机制：**

> 到第 10 个展示日，参与的 30 颗变成 24 颗；保留的 70 颗不变，总松果从 100 变成 94，还剩 10 个展示日。
> 你预计那时会有多不舒服？
> 你更可能：继续／收回一半／全部收回／还不知道。

正式摘要的数字直接取自选定情境的节点计算值；不能先固定“少 6 颗”，实际却让用户在“少 9 颗”时作答后强行配对。节点摘要来自事先选案，意味着用户知道将经历的节点结果；**本模块比较摘要预想与过程体验，不宣称制造了意外损失或完成了盲测**。

**感受选项：**没有不舒服／轻微／明显／强烈／暂时说不清或不回答。最后一项记 `null`，不当成最低等级。前后使用相同措辞，不把四档当作等距心理量表，不计算“承受力百分比”。

**节点处操作：**继续 `keep`／收回当前参与份额的一半 `reduce_half`／全部收回 `close_all`。实际操作改变后续模拟敞口，不只是问“你会怎么做”。收回指参与份额，不是总账本的一半；按 §7 增量约定，在下一展示日的开盘参考价执行，不承诺正好收回节点显示的数额。

**退出与收回不同：**“退出试航”是结束体验，记 `cal_exit`，不自动当成 `close_all`，更不能当成“承受不了”。跳过感受问题可以继续操作；拒绝操作时可以返回结果，不自动默认 `keep`，也不推算其后续个人结算。

**补充问题：**

- 原因（可多选）：实际感受与预想不同／对后面走势的判断改变／刚才没理解清楚数字或规则／只是想试试操作／其他或不确定。不把“改变行情判断”与“感受变化”强行设为互斥。
- 在意程度：在意这次变化／不太在意，只是试试／说不清或不回答。“没有不舒服”不自动等于“不在意”。

### 2.4 对 §3 的追加说明

校准情境使用 `SC1`，不得复用用户已看过结局的 R1—R6 或任务情境。它不属于第三幕，不计入 O1—O3 的两次一致、不触发 O4、不贡献物种首翻和 `backed_families`。

## 3. 插入 §4.6：校准事件、可比性与规则

### 3.1 独立事件

沿用会话、`event_id`、情境 ID、内容版本和阶段，新增 `module="self_calibration"`、`attempt_id`、`checkpoint_id`、`seq`、`calibration_rules_version` 和 `source`。`source` 为真实体验记录 `user_session` 或评委模拟 `judge_simulation`；真实体验仍是虚拟游戏，不代表真实交易。

| 事件 | 关键字段 | 约束 |
|---|---|---|
| `cal_start` | 告知版本、用户确认、情境版本、账本、是否已有该情境暴露 | 跳过不创建假体验；重玩保留原尝试 |
| `cal_forecast` | 节点摘要 ID／校验值、预期感受、预期操作 | 本次过程展示前提交并锁定；允许未知／跳过，不事后补填 |
| `cal_exposure` | 分段 ID、可见截止点、账本快照、内容校验值 | 系统记录真正展示过的内容；预加载不等于用户已经看过 |
| `cal_response` | 节点 ID、当下感受、对应暴露事件 ID | 必须在结局揭晓前；缺失不由操作或停留时间推断 |
| `cal_action` | `keep/reduce_half/close_all`、决策节点、待执行规则 | 每节点一次；是操作指令，不伪装成已经按节点价格成交 |
| `cal_followup` | 原因选项、在意程度 | 可跳过，分别标明自述与缺失，不证明原因唯一 |
| `cal_revision` | 新的预期、是否已经看过结果／反馈 | 新事件，不覆盖 `cal_forecast`，不拿来缩小旧差异 |
| `cal_exit` | 发生阶段、`skip/exit`、退出前已完成事件 | 在入口跳过只记 `stage=offer, reason=skip`，不伪造 `cal_start`；退出不算收回或低承受力，保留已合法采集的节点观察 |
| `cal_practice` | 练习 ID、模拟参与量、重新表达的计划 | 只记练习完成情况，不新增独立校准证据或 O1—O5 |

事件顺序使用 `seq` 校验，不把反应速度、鼠标轨迹、暂停次数或退出速度解释成人格。重复点击按事件／节点去重，不重复计数。

**首个节点分析窗口：**`cal_forecast` 在首段过程暴露前；`cal_response`、`cal_action` 和用于原因说明的 `cal_followup` 在该节点之后、任何后续段或结局暴露之前。窗口之后的补充单列为事后说明。

### 3.2 可比性校验：先校验，再描述差异

`comparison_basis="summary_vs_path_experience"`。校验的是摘要与实际节点的对应性，不代表用户前后掌握的信息完全相同。

以下必须一致：情境及内容版本、起始账本、参与量、比较节点、参与部分现值、总账本现值、已过／剩余展示区间、可执行操作及执行规则。精度从同一计算结果派生，前后用同一显示舍入方式；不可用粗略区间掩盖实质不同的损失。

同时检查：用户确实看到该节点；预测发生在过程暴露前；反应发生在后续结果暴露前；期间没有改变账本／规则；没有把同一情境重玩伪装成首次。

**仍有局限：**过程中的跌落速度、此前涨跌、路径信息与情绪不同，本来就是体验的一部分。即使节点数字对应，也不能据此声称“完全控制了信息，只测出情绪效应”。P0 不做这种因果识别。

### 3.3 规则与输出

不新增 O6，不套用能力层的 ✅／🤝，不设置人格分数。`status` 与两个对照轴分开存储。

**状态规则按顺序取第一条命中：**

| 规则 | 条件 | `status`／显示 |
|---|---|---|
| SC-00 | 未进入或明确跳过 | `not_started`／`skipped`；未观察，不等于没有差异 |
| SC-01 | 版本、节点、账本或事件顺序不匹配；反应在结局之后才提交 | `not_comparable`；说明哪项不对应，不输出校准推断 |
| SC-02 | 已看过同一情境过程／结局，或本地记录表明是重玩 | `practice`；可展示练习记录，不增加独立证据 |
| SC-03 | 用户明确表示“不太在意，只是试试”或仅测试操作 | `low_involvement`；保留记录，但不足以支持承受感受的推断 |
| SC-04 | 未到对应节点，或感受与行动两轴都没有一组完整的前后记录 | `insufficient`；显示缺少什么，不补造答案 |
| SC-05 | 通过匹配，且至少有一个完整的前后对照轴 | `paired_observation`；仅描述本次差异，单列缺失字段与未知项 |

退出发生在有效采集完成之后，不自动删除此前合法的对照；在到达节点之前退出则没有匹配反应。`not_comparable` 是资料不能对应，不是用户“表现不合格”。

**感受轴，限可比较记录且前后感受均非空：**

| 规则 | 条件 | `feeling_relation`／文案 |
|---|---|---|
| SC-F1 | 当下所选等级高于预期 | `more_intense`：你这次报告的不适比预想更强 |
| SC-F2 | 当下等级低于预期 | `less_intense`：你这次报告的不适比预想更轻 |
| SC-F3 | 相同等级 | `same_category`：这次两次选择落在同一档；不代表体验完全一致 |
| SC-F0 | 任一缺失或状态不支持比较 | `unknown`：暂时没有可用对照 |

**行动轴，限可比较记录、预期操作明确且实际操作已提交：**

| 规则 | 条件 | `action_relation`／文案 |
|---|---|---|
| SC-A1 | 两次操作相同 | `same`：本次操作与事前预期相同 |
| SC-A2 | 两次操作不同 | `changed`：本次操作与事前预期不同，原因尚需结合当时的信息与自述 |
| SC-A0 | 预期还不知道／缺实际操作／状态不支持比较 | `unknown`：未形成可比较的行动记录 |

F/A 正式结论只在 `paired_observation` 状态产生；其他状态仍可显示原始两列，但派生关系为 `unknown`，不得用醒目的“差距已证实”标题包装。

原因选项作为 `reported_reasons` 原样保留，所有结果的 `causal_attribution` 均为 `not_established`。在意程度未回答时标 `engagement=unknown`，允许报告前后选项的描述性差异，但必须说明投入程度未知，不能自动写成高质量校准。

**必须避免的推断：**提前收回不等于扛不住；坚持不等于承受力强；感受比预期强但仍继续，也属于感受差异；改变后续走势判断可以与感受差异同时存在。没有差异不证明具备真实承受力，更轻松不构成增加现实风险的推荐依据。

## 4. 插入 §5.5：校准后的可选下一步

原 `recommend` 的 A/B 路线、主题与帮助档位不改。单独输出 `calibration_support`，展示为“还有一个与刚才有关的小练习”，用户可先继续研究任务。它不是必须通过的任务 C，不影响 `ready_for_B`。

**最小练习：「同样的风浪，换一种安排」**

复用刚才的已知走势，允许在 10／20／30 颗等预设模拟参与量之间切换，其他松果保留。对照相同节点及完整路径的总账本变化；明确这是“假如当初采用另一种参与量”的事后练习，不是重新预测市场或新的独立测评。P0 不做增加到更高参与量的奖励机制。

示例中，参与部分变为原来的 80% 时，分别参与 10／20／30 颗，总账本会是 98／96／94 颗。真实页面使用本情境数据计算，不把这段历史的最大减少当成未来最坏情况。

若练习要展示尚未见过的后续区间，先提示“接下来会揭晓后续”，并记录暴露。此后的作答不能补成结局揭晓前的首次节点反应。

完成时可选一句计划：“先算清总账本会变化多少”“信息变化时先重新核验”“感受比预计强时先暂停，再决定”。没有标准答案；只记用户选择，不把“继续承受”设为进步方向。

**补充引导按顺序匹配一个主要入口：**

| 规则 | 条件 | 补充引导 |
|---|---|---|
| SC-R1 | 明确表示没理解数字／规则 | 先看“参与的那部分”和“总账本”的差别；不自动改 O1—O5 或原帮助档位 |
| SC-R2 | `not_comparable/insufficient/low_involvement`，或跳过 | 说明为何无法判断；继续原流程。不加大刺激，不要求重玩到出现差异 |
| SC-R3 | 原因包含“对后面走势的判断改变” | 回看节点前哪些信息改变了判断；仅作自述回顾，不直接记为 O4；感受差异仍独立保留 |
| SC-R4 | `paired_observation` 且 `feeling_relation=more_intense` | 建议上述参与量对照与暂停计划；不推荐真实仓位，不说“你应该永远保守” |
| SC-R5 | `paired_observation` 且其余情况 | 提供前后回顾和可选练习；更轻不鼓励加大风险，同档不颁发承受力认证 |
| SC-R0 | 其他，如仅练习模式 | 继续原任务，保留自我回顾入口，不声称形成新校准证据 |

用户同时报告判断更新与感受变化时，两条事实都展示；表中顺序只决定先推荐哪个入口，不消除另一条观察。用户主动选练习或帮助方式优先，不强行覆盖。

## 6. 对 §7 的增量：选案、数据隔离与结算

### 6.1 选案与前后对应

新增一个未向该用户展示过的、具有完整执行价格与结算区间的情境。优先从获准的 Panda Data 数据中选取。起止时点、节点、参与量、展示方式及规则在收集玩家回答前冻结，不能根据“用户说能扛多少”继续加深损失，不能为了制造反差而自适应选后续走势。

与原六轮的事实核验目的不同，校准模块可以**事后筛选包含减少节点的教学案例**，但要在入口及来源页明确披露 `selection_uses_future=true`；它不是可交易信号、市场随机样本或点时策略。不得冒称满足原六轮的“仅根据决策前信息选案”。

节点摘要使用已选案例的真实计算值，只公开本模块已经声明的条件信息；后续过程与最终结局按阶段加载。30→24 只是示例，不缩放、篡改真实涨跌来强行满足它。首次只选一个节点；以后新增情境另有版本和暴露记录。

### 6.2 文件拆分与时间边界

新增 `calibration_manifest.json`（告知、摘要、账本、节点、执行规则和版本）与按阶段拆开的 `calibration_SC1_segment_*.json`。来源记录沿用原 §7 的接口、标的、区间、复权、分红、缺失处理、脚本版本与授权要求，另加节点选择方式和摘要来源。

原 §7 “揭晓前不加载未来数据”对本模块具体化为：

- 预测前仅加载明确公开的节点摘要与必要的背景，不加载通向节点的完整路径或最终结局；摘要属于主动披露，不伪装成用户原本不知道的信息。
- 预测锁定后加载到节点为止的分段；反应和操作锁定前不加载节点之后的段。不得由预取、整体 JSON 导入或预缓存提前带入后续数据。
- 感受与操作关联的内容快照可核查；后续补充不能回填到该快照之前。
- 静态站点的分段加载只能约束正常交互，不是防止技术用户通过开发工具获取公开资源的安全屏障，不宣称防作弊。已知提前看过者标为练习／不可比较；无法检测的外部提前获知列为局限。

### 6.3 独立账本与执行口径

为避免按看过的收盘价倒填成交，沿用主线的时间边界思想，但使用独立计算：

1. 初始参与在 T+1 日开盘参考价建立：`cash = 100 - 30`，`units = 30 / open[T+1]`。这里是理想化份额模拟，不代表真实可成交的股数。
2. 节点设在 T+k 日收盘，`1 ≤ k < 20`；节点账本为 `cash + units × close[T+k]`。感受和预测都针对这个**操作前**状态。
3. 用户在看到节点之后提交操作。收回一半：`sold_units = units / 2`；全部收回：`sold_units = units`；继续：`sold_units = 0`。
4. 在下一展示日 T+k+1 的开盘参考价执行：`cash += sold_units × open[T+k+1]`，`units -= sold_units`。明确提示实际模拟收回数可能与节点显示的估值不同。
5. 后续总账本为 `cash + units × 当前参考价`。若用户选择查看完整结算，T+20 收盘按同口径结算剩余份额；只结算剩余份额，不能再把原始 30 颗重复返还。

本模块不计真实交易费用、滑点、最小交易单位或成交限制，必须标明理想化模拟。必要价格缺失则不发布该情境，不静默拿同日收盘价替代执行。P0 无加码、杠杆或第二次调仓。

**计算验收示例（人工数据，非行情）：**初始价 100，参与 30，持有 0.3 份，现金 70；节点价 80，总额 94。选择收回一半，次日开盘价 82，则收回 0.15 份得到 12.3，现金变为 82.3，剩 0.15 份。终点价 90 时总额为 95.8。全部收回时为 94.6；继续时为 97。节点校准都基于操作前的 94，而不是事后结算金额。

## 9. 对 §10—§12 的增量：演示、局限和告知

### 9.1 演示与试玩

- 本模块只对照虚拟情境中的预测、感受自述与操作；没有真实资金损失，也没有现实财务资料。不能识别真实亏损阈值，不能声称属于有效的风险适当性测评。
- 情境节点事先以摘要披露，案例按减少情境选择；不能解释成遭遇未预期冲击，也不能代表市场通常怎样发展。
- 看过过程意味着获得了新信息，感受、信念、界面理解、尝试按钮等因素可能共同改变操作；P0 不作心理原因的因果鉴定。
- 一次体验不能证明稳定特质；相同档位不证明没有任何差异。相同案例重玩、已知结局及参与量回放都是练习，不是额外的独立证据。
- 清除本地记录或跨设备后无法可靠识别曾经看过案例；P0 无账号系统，不能宣称完全识别首次体验。

| 风险 | 新增降级 |
|---|---|
| 找不到完整且获准展示的真实案例 | 可用明确标注的人工示例演示流程，不声称该模块已接入真实数据 |
| 节点或前后条件对不上 | 保留体验记录，不输出差异结论；不能放宽匹配条件制造结果 |
| 来不及实现下一日执行与正确账本 | 不发布虚假的“收回影响结算”；降为只读体验／感受报告，并明确行动执行未完成 |
| 虚拟变化没有投入感 | 显示信息不足，保留教学回顾；不加真钱、不惩罚、不不断升级压力 |
| 第二个独立情境未完成 | 保留“仅本次”结论，不把练习回放称为复核 |

补充成功标准：**用户不仅看到自己是否改变了选择，还能说清“我的感受与预想哪里不同、哪些原因还不知道，以及下一次准备怎样安排”。** 不以更能扛、更少退出或更高松果结算作为成功标准。

### 9.3 告知与隐私增补
