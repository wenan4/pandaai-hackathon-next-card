# 冒险素材体积与加载建议

## 五张素材的编码结果

以下由本地 Pillow 11.1.0 / libwebp 1.5.0 编码，WebP 有损质量 90、编码方法 6、alpha 质量 100；不裁切、不缩放、不重绘，原始 PNG 均保留。色彩采用有损压缩，因此 RGB 并非逐像素相同；四张带透明通道的图片经逐像素比较，alpha 与 PNG 完全相同。

| moss | 1247 × 1261 | 2,174,537 | 475,488 | 78.1% | alpha 完全一致 | 31.80 dB |

| **合计** | — | **11,604,075** | **2,116,116** | **81.8%** | — | — |

PSNR 仅作为编码差异的参考：透明图计算覆盖 alpha 非零的像素，不能替代实际观看。五张 PNG 与 WebP 已在浅色的 500 × 580 像素容器和深色的 190 × 225 像素容器内并排检查：构图、主体轮廓、透明边缘和小尺寸识别保持一致；clock 鸟下方没有重新出现球。该目视检查不是对所有显示器的无差异保证。

表格是未压缩文件字节的对比；页面只会传输实际请求的素材，具体节省取决于用户走到哪些页面及缓存状态。原图仍保留在 `public/`，因此构建产物中同时包含 PNG 和 WebP，**仓库和部署包总大小不会因保留原图而减少**。不缩小像素尺寸也不保证解码内存下降；页面加载时间及 LCP 改善需要在实际网络环境中测量。

## 本地复现

需要支持 WebP 的 Pillow；只用于离线构建，不增加前端运行依赖。在仓库根目录运行：

```powershell
python scripts/optimize_adventure_art.py
```

脚本自动扫描 `public/art/adventure/` 中全部 `.png`，为每个原图生成同名 `.webp`。也可只增量编码新文件：

```powershell
python scripts/optimize_adventure_art.py --only traveler.png
```

写入前脚本重新解码候选图，检查尺寸和透明通道，失败则保留原有目标文件；不会修改或删除 PNG。已使用包含 RGB、透明边缘、全透明图片的临时输入核验自动发现、原始文件字节不变、尺寸和 alpha 保持；五张图片在所列工具版本的重复编码中输出哈希一致。不同 libwebp 版本可能产生不同字节，即使视觉与规格一致。

## 可执行的网络层建议

1. 页面引用同名 WebP，并以项目的 `BASE_URL` 解析素材地址，确保根路径和子路径部署都正确。透明对象保持现有尺寸和布局；如需兼容不支持 WebP 的旧浏览器，再以原 PNG 提供回退。PNG 和 WebP 不应在常规页面同时预加载。
2. 在 CDN 对 Vite 生成的带内容哈希的 `assets/` 文件使用较长缓存，例如 `Cache-Control: public, max-age=31536000, immutable`；HTML 使用 `no-cache` 以便及时获取新入口。`public/art/adventure/` 下当前 WebP 文件名不带哈希，先采用短缓存和过期后重新验证，或将资源改为内容哈希命名后再用 `immutable`，避免更新后长期显示旧图。
3. 优先请求首屏实际出现的背景；敌人和后续角色按出现时加载。只有在测量证明背景是首屏 LCP 时，才考虑对该背景进行一次精确 URL 的图片预加载，并避免在旧版入口无条件预加载冒险资源。用浏览器网络面板核对无重复请求，并在部署环境确认返回 `image/webp`。
4. 冒险版中文目前优先使用系统字体；数字和英文使用本地 IBM Plex Mono，`font-display: swap` 已允许先显示回退字形。若确认只需拉丁字符，可将完整 `500.css` 换成本地 `latin-500.css` 再核查字符覆盖；浏览器会根据字形与 `unicode-range` 按需取字体，构建目录中存在多个子集不等于用户会全部下载。旧版入口的中文装饰字体体积较大，应维持按旧版入口加载，不要把它加入冒险首屏预加载。
5. 优化前后用同一设备、网络限速和冷／热缓存条件比较首屏请求数、下载字节、LCP 与关键页面画质；不要根据文件体积直接声称已测得某个加载时间或性能分数。本次只验证资源本身和脚本，未做生产环境性能压测。
